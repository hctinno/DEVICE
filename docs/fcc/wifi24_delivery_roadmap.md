# 스마트폰 Wi-Fi 2.4 GHz b/g/n — 완성까지의 7단계

작성일: 2026-10-23 (Asia/Seoul). 상태: 현재 코드와 [설계 검토안](../superpowers/specs/2026-10-23-smartphone-wifi24-bgn-design.md)에 근거한 작업 분해 제안. 일정 약속이나 구현 완료 보고가 아니다. 기존 설계의 A~D를 7개의 산출물로 풀어 쓴 문서이며 제품 범위를 확장하지 않는다.

## 1. AI 하네스의 역할

AI 하네스는 기존 모델이 이 시험소의 업무를 계속 수행하게 하는 실행 시스템이다. 시험건 상태와 규격 근거를 모델에 제공하고, 다음 작업의 제안과 도구 호출을 검사하며, 결과·대기·중단·복구를 기록하고 이어 간다. 모델 API만 연결하거나 MCP 서버만 켜는 것으로 이 기능이 완성되지는 않는다.

| 구성 | 맡는 일 | 현재 기반과 남은 일 |
|---|---|---|
| 규격·제품 지식 | 원문/판본/조항, 제품 사실과 출처, 적용성·필수 입력·시험 조건 | 수집 대장·자료 인수·제품 facts 저장 기반 있음. 실제 문서 해석과 b/g/n 규칙/방법은 새 작업 |
| AI 하네스 | 폴더/응답 이벤트, 영속 작업, 모델 문맥과 도구 선택, 전제 확인, 예외 요청, 제한된 복구, 재개, 완료 판단 | DB와 이벤트 기록을 재사용. 모델 작업자·자동 진행·큐/복구·현장 사용자 응답 처리는 미구현 |
| MCP 및 DUT/장비 실행기 | 구조화된 도구 호출, 시료/장비 세션·잠금, 검증된 명령, 실제 RF 상태 확인, 원본 취득·정지 | 오프라인 MCP 11개 도구 있음. live 제어 어댑터와 세션 관리는 미구현 |
| 계산·커버리지·성적서 검증 | 보정·단위·한계값·불확도·필수 항목 검사, 출처 있는 표/그래프, PDF와 리뷰 | 공통 계산 2개와 초안 PDF 기반 있음. b/g/n 방법별 처리·완료 판정·AI 리뷰는 미구현 |

AI는 적용성·조건·순서를 근거와 함께 제안하고 허용 범위에서 실행을 이끈다. 수치 계산과 장비 동작은 검증된 코드/절차를 사용한다. 모델이 낸 ‘완료’ 문구만으로 시험건이 완료되지 않는다. MCP는 호출 인터페이스이며 하네스의 상태·자동 진행 기능은 별도로 구현한다.

## 2. 7단계와 완료 증거

아래 비중은 **향후 작업을 배분하기 위한 설계자의 초기 공수 추정**이다. 합은 100%이며 현재 진행률·측정 정확도·일정 달성률을 뜻하지 않는다. 최초 제품/제조사 도구 프로필 한 조합과 범위에 필요한 장비/사이트가 준비될 것을 가정한다. 새 장비·도구 지원, GUI만 있는 제어, 현장 결함과 재검증이 늘면 비중과 총공수를 다시 산정한다.

| 단계 | 구현·확인할 작업 | 단계 완료 증거 | 초기 공수 비중 |
|---|---|---|---:|
| 1. FCC 시험 기준 구축 | §15.247와 연관 조항/방법의 판본·적용 조건, 필수 제품 사실, 시험·증거·보고 요구, 최악 조건 선정과 예외 규칙 | 모든 범위 항목이 확보·검토한 근거 및 실행/검토 조건에 연결됨. 누락 원문을 현행 방법으로 가장하지 않음 | 10% |
| 2. 폴더 접수·제품 판단 | 문서/OCR 인수, 고객·제품·시료·HW/FW 식별, 출처 연결, 누락/충돌 검출, 시험/장비 준비 목록 | 정상/누락/충돌/미지원 사례에서 기대한 제품 사실·질문·시험계획을 생성 | 10% |
| 3. AI 하네스 | 상시 서비스, 영속 작업 큐, 모델 API·문맥/도구 호출, 상태 전이 검사, 사용자 응답, 중단·재시작·재개, 실행 한계 | 같은 셋업 내 정상 흐름에 사람의 단계 지시가 필요 없고, 중복 이벤트/세션 종료/모델 오류 후 잘못된 중복 실행 없이 복구 | 15% |
| 4. 첫 실장비 흐름 완성 | DUT·계측기 어댑터, 연결 요청·검증, 시험모드와 실제 RF 확인, 전도 출력 측정·원본·계산·단일 항목 PDF/리뷰 | 실제 스마트폰/제조사 도구/계측기 한 조합에서 접수부터 전도 출력 성적서까지 연결하고 독립 기준 측정과 대조 | 20% |
| 5. b/g/n 전체 시험 확장 | 6 dB BW·출력·PSD·대역외/대역 경계·방사 불요파·해당 AC 시험, 모드/채널/대역폭/체인·최악 조건, 셋업 변경·교정/보정·불확도 | 범위 내 모든 적용 측정·검토 항목에 검증된 방법·실행·원본이 있고 비적용/보류/실패를 구별 | 20% |
| 6. 전체 성적서·자동 리뷰 | 방법별 표/그래프/사진·설명, 출처/원본 추적, 결정적 검사와 AI 리뷰, 수정/허용 재측정·재생성, 결과물 묶음 | 전체 범위의 PDF에서 원본까지 역추적·재계산 가능. 부적합은 그대로 보고하고 미완료/합성 자료 혼입은 차단 | 10% |
| 7. 현장 검증·운영 전환 | 독립 기준 비교, 반복 운전·경계/장애 사례, 무인 재개, 설치·상태 감시·자료 백업/복원, 버전 변경 시 재검증, 기관 발행 정책 연결 | 선언한 지원 범위에서 정상 시험건의 일상 기술 개입 0회와 측정/보고 정확성 입증. 실패·중단·부분 보고도 검증 | 15% |

단계 4의 PDF/리뷰는 전도 출력 한 항목을 대상으로 단계 6의 기능 일부를 먼저 만든 것이다. 단계 6에서 전체 범위의 보고·리뷰로 확장한다. 단계 7은 앞 단계의 시험을 처음 시작하는 시점이 아니라 이미 검증한 부분들을 실제 업무로 통합 검증하는 단계다.

## 3. 실제 작업량의 단위와 순서

첫 완료 대상의 최소 범위는 다음과 같이 관리한다. 최소 조합을 검증했다고 다른 모델·펌웨어·체인을 검증한 것으로 넓혀 쓰지 않는다.

- 공통 AI 하네스와 접수/판단 흐름 각 1개.
- 지원 범위를 명시한 제조사 DUT 제어 프로필 최소 1개. 새 도구/버전의 지원 작업은 별도 증가분이다.
- 전도 RF·방사·해당 AC 측정에 필요한 실제 장비/사이트 구성. 장비 모델 수는 해당 구성 확인 후 정한다.
- 위 표의 6개 측정 방법군과 안테나·셋업·출력 목표 검토. 제품 지원 구성에 따른 실제 측정 횟수는 시험계획에서 산출한다.
- 전체 범위 성적서/리뷰 흐름 1개, 지원 조합별 기준 비교·반복·예외 검증 묶음.

단계 1의 자료 인수/규칙화와 단계 2·3의 공통 개발은 함께 진행할 수 있다. 문서가 아직 없어도 상태·어댑터 계약과 합성/재생 시험은 개발할 수 있다. 실제 측정 방법의 실행 가능 상태와 적합 판정은 원문/절차 검토 전 활성화하지 않는다.

첫 실물 연결을 마지막까지 미루지 않는다. 실제 도구·현장 접근이 준비되면 단계 4의 좁은 흐름을 먼저 검증해 명령 방식·권한·응답·측정 동기화·복구 문제를 드러낸다. 단계 5의 각 방법을 추가할 때마다 단계 6의 해당 보고 부분도 함께 완성한다.

기존 설계와의 대응은 A=주로 1·2·3, B=4 및 6의 최소 기능, C=5·6, D=7이다. 기존 전체 시험소의 로봇·KC/EU 단계와 이 7단계를 혼합해 완료율을 계산하지 않는다.

## 4. 현재 위치

2026-10-23 코드 확인 기준:

- 장비 등록 6,470행 DB, 규정/매뉴얼 수집 대장과 인계 체계가 있다.
- `labflow/schema.sql`, `store.py`, `intake.py`, `workflow.py`는 자료·시험건·계획·오프라인 실행·원본 해시·이력을 제공한다. 제품 문서 자동 해석이나 실장비 실행을 의미하지 않는다.
- `labflow/mcp_server.py`는 오프라인 도구 11개를 제공하며 `live_hardware`, `automatic_regulatory_applicability`, `official_release`는 false다.
- `labflow/calculations.py`의 두 계산기는 전계 보정과 dBm→W 공통 산술이다. 완성된 FCC 시험방법 두 개가 아니다.
- HTML/PDF/JSON 초안 생성 기반이 있다. 방법별 전체 표/그래프·AI 리뷰·발행 기능은 남아 있다.

따라서 공통 기반 일부를 재사용할 수 있지만 위 7단계의 완료 게이트를 통과한 단계는 아직 없다. 설계·문서 수나 과거 단위 테스트 수를 전체 구축 완료율로 바꾸지 않는다.

## 5. 언제 목적이 완성되는가

현재 목적의 완료는 선언한 스마트폰 2.4 GHz b/g/n 지원 범위에서 다음이 실제로 재현될 때다.

1. 충분한 고객·제품 자료 업로드와 필요한 물리 셋업 후, 사람이 시험항목/조건 선택·단계 지시·수치 전사를 하지 않아도 전체 범위의 측정·성적서 PDF·AI 리뷰가 끝난다.
2. 자료 부족·미지원 구성·물리 변경·복구 불가에는 이유와 재개 조건을 가진 요청이 생기고, 해결 후 영향을 받는 부분부터 이어진다.
3. 기준 측정과 사전에 정한 허용 차이·판정 규칙을 충족하고, 모든 보고 수치가 실제 원본·방법·보정·시료/장비로 추적된다.
4. 부적합은 부적합으로, 미완료는 미완료로 남고, 외부 연관 근거·기관 발행 준비 상태를 RF 측정 범위 완료와 구분한다.
5. 중단·재시작·변경·자료 복원 시 잘못된 원본이나 이전 셋업을 재사용하지 않고 운영 상태를 복구한다.

RF exposure 연관 근거와 발행 정책의 처리, 첫 셋업 이후에도 필요할 수 있는 물리 작업은 설계 검토안의 기준을 따른다. 이 완료는 스마트폰의 모든 무선 기능·다른 국가 규정·자동 배선까지의 완료가 아니다.

달력상 기간과 총 인일은 아직 산정하지 않았다. 제조사 도구의 실제 인터페이스, 현장 접근/운전 시간, 장비·옵션·교정·사이트 준비 상태가 미확인이다. 단계 1의 원문 검토와 단계 4의 최초 제어/측정 검증에서 이 변수를 확인한 뒤 범위별 공수·외부 대기·실측 시간을 분리해 산정한다. 초기 비중을 주수/개월 수로 임의 변환하지 않는다.

## 6. 담당과 바로 다음 산출물

수집 담당은 [b/g/n 첫 배치](../../handoff/WIFI24_BGN_FIRST_BATCH.md)의 원문·방법·공개 사례·매뉴얼을 GitHub로 준비한다. 현재 에이전트는 이를 규칙·방법에 연결하고 접수/하네스/실행/보고를 개발한다. 사용자는 현장 통합 시 실제 제조사 패키지·시료·연결 가능한 장비/사이트와 물리 셋업을 제공한다. 수집 담당에게 전체 개발을 인계하지 않는다.

가장 먼저 사용자에게 보여 줄 동작은 **자료 폴더에서 제품 요약·누락/충돌·시험 목록·필요 장비/셋업을 자동 생성하고, 보완 자료가 들어오면 상태를 갱신하는 것**이다. 그다음 실제 전도 출력 한 항목의 전체 흐름을 완성한다. 나머지 규격 전부나 장비 대장 전 모델의 제어를 먼저 구현할 필요는 없다.
