# FCC 과거 시험 재현용 자료 명세

목적은 기존 시험 건의 제품 정보부터 원시 측정값·계산·판정·성적서까지 재현해 새 시스템의 검증 기준을 만드는 것이다. 아래는 요청/수집할 자료 목록이며 실제 데이터 확보를 뜻하지 않는다.

2026-10-23 추가 답변: 사용자는 기존 성적서·원시 데이터·SOP를 보유한다. 현재 파일은 미제공이다. 기존 양식을 기준으로 새 구조를 고정하지 않고 규격·표준 시험방법에서 형식을 먼저 설계한다. 기존 자료는 이후 변환 및 독립 재현 검증에 사용하며, 공개 원천 수집이나 공통 형식 설계의 선행조건이 아니다.

## 시험 건별 기본 묶음

| 자료 | 필수 연결 정보 | 확인 목적 |
|---|---|---|
| 의뢰서·제품 사양 | 프로젝트 ID, 모델/변형, HW/FW, 시장·신청 경로 | 적용 규정과 범위의 입력 |
| 기능·송신 구성 | 주파수·모드·대역폭·채널·안테나·출력·동시송신·사용 조건 | 시험 조합과 노출 평가의 입력 |
| 당시 적용 규정 | CFR 조항, KDB 첨부 ID/버전, 표준 판본, SOP 버전, 전환 근거 | 과거 규정으로 재현할 기준 |
| 계획·기술 검토 | 시험 목록·제외 사유·최악 조건 선정·계획 승인 기록 | 시험 누락 및 판단 검증 |
| 시료·셋업 | 시료 ID, 지원기기, 배선·지그·안테나·거리·위치, 시험 당시 사진 | 측정 구성의 재현 |
| 원시값·설정 | 장비 원시 파일, 측정 시각, RBW/VBW/검파기/트레이스 등 해당 설정 | 계산과 측정 유효성 검증 |
| 보정·교정·사이트 | 적용한 보정표, 교정 정보, 사이트 조건, 불확도 예산 | 수치의 변환 근거와 측정 능력 |
| 계산·판정 | 계산 시트/코드, 단위·반올림 규칙, 한계값 출처, 판정 방식 | 독립 재계산과 경계값 검증 |
| 성적서·개정 | 최종본과 수정 이력, 보고서 번호, 검토·발행 기록 | 출력 일치와 누락 검증 |
| 질의·문제 사례 | TCB 질의, 재시험 요청, 부적합, 데이터 무효, 시료 변경 | 정상 흐름 밖의 동작 검증 |

## 선별 기준

- 원본과 사용권을 확인하고, 고객 정보의 처리 범위를 정한다.
- 성공한 시험뿐 아니라 불합격·무효·불완전 자료·규정 적용 오류 사례를 포함한다.
- 서로 다른 제품군, Certification/SDoC, RF·방출·RF exposure 분기, 복합/모듈/변경 사례를 규정군별로 확보한다.
- 보고서 PDF만 있는 건은 서식·문서 검토용으로 표시한다. 수치 재현용 기준 사례와 구별한다.
- 동일 제품군·동일 원시 측정에서 파생된 여러 보고서를 서로 독립적인 검증 사례로 세지 않는다.
- 개발·규칙 보완에 사용한 자료와 최종 평가 자료를 구분한다. 최종 평가 자료의 정답을 생성 단계에 노출하지 않는다.
- 허용 차이와 판단 규칙은 비교 결과를 보기 전에 정한다. 기존 보고서가 틀렸을 가능성도 검토한다.
- 과거 판본으로 재현하는 평가와 현행 판본으로 재판정하는 평가는 별도 작업이다.

## 기준 사례 인덱스 필드 제안

`case_id`, `case_version`, `product_profile_id`, `sample_id`, `authorization_route`,
`rule_scope_ids`, `source_version_ids`, `sop_version_ids`, `test_plan_id`,
`raw_data_manifest`, `setup_photo_manifest`, `calibration_refs`, `correction_refs`,
`expected_results`, `expected_applicability`, `expected_report_requirements`,
`reviewer_record`, `known_defects`, `allowed_tolerances`, `dataset_split`,
`license_or_usage_permission`, `confidentiality_level`.

이 파일은 자료 구조 제안이다. 측정 데이터·사진·합격 값은 생성하지 않았다.
