# 규격에서 도출하는 FCC 성적서·측정 데이터 형식 초안

작성일: 2026-10-23. 사용자 방향: 기존 성적서·원시 데이터·SOP를 보유하고 있지만, 그 양식에 새 시스템을 맞추지 않는다. FCC 규정 및 해당 시험방법에서 공통 형식과 시험별 확장 필드를 먼저 도출하고, 기존 자료는 이후 변환·재현·누락 검증에 사용한다.

현재 결과는 **확인된 FCC 공통 요구사항에 근거한 구조 초안**이다. 최신 KDB 첨부와 라이선스가 필요한 표준 본문을 확보하고 검토한 뒤, 시험별 설정·계산·한계값·보고 항목을 확정한다. 아직 검토하지 않은 표준의 세부 절차를 이 양식이 충족한다고 주장하지 않는다.

## 설계 기준

1. **규정 요구사항 → 필요한 증거 → 측정 기록 → 계산/판정 → 성적서 항목**의 연결을 먼저 정의한다.
2. 장비가 생성한 원시 파일은 그대로 보존한다. 표준화 CSV/JSON은 별도 변환본이며, 장비 원본의 파일·해시·위치를 참조한다. 원래 파일을 새 양식으로 덮어쓰지 않는다.
3. 동일한 검토 완료 결과에서 RF 성적서, EMC 성적서, 내부 워크시트 및 제출 패키지를 만든다. 보고서 작성 중에 별도의 수치를 수작업으로 생성하지 않는다.
4. 공통 기록은 모든 시험에 재사용하고, 검파기·RBW/VBW·스윕·SAR/DFS 등의 상세 설정과 증거는 시험방법별 프로필로 확장한다. 한 가지 측정 행으로 모든 시험을 표현하려 하지 않는다.
5. 실제 시험 구성, 방법·규정 판본, 계산 코드, 보정표와 결과를 고정 ID로 연결한다. 이전 기록 수정 대신 새 개정과 대체 관계를 남긴다.
6. 실행 상태, 데이터 유효성, 규정 판정, 보고서 검토 상태를 각각 관리한다. `실행 완료`가 `유효` 또는 `적합`을 뜻하지 않는다.

## 제안하는 성적서 구성

| 순서 | 내용 | 주요 연결 |
|---|---|---|
| 1 | 문서 번호·개정·시험 범위·발행 상태·검토 기록 | 보고서 ID, 해당 결과와 이전 개정 |
| 2 | 신청자·제조자·시험소·시험 장소·시험일 | 프로젝트, 시험 실행 |
| 3 | EUT 모델·일련번호·HW/FW·시료·안테나·전원·기능 | 제품 프로필과 실제 시료 |
| 4 | 적용 규정·신청 경로·표준/KDB 판본·전환 조항 | 규정 스냅샷, 적용 판단 |
| 5 | 시험 항목과 적용/비적용 근거·결과 요약 | 시험계획, 미해결 항목, 개별 결과 |
| 6 | 동작모드·채널·대역폭·최악 조건·주변기기·케이블·수정사항 | 시험 구성과 선정 근거 |
| 7 | 시험방법·실제 설정·장비·교정·사이트·환경 | 방법 프로필, 실행 시점 기록 |
| 8 | 시험별 결과·표/그래프·조건·한계값 근거·계산 예시 | 원시 파일, 계산, 판정 |
| 9 | 실제 셋업 도면/사진·제품 사진의 참조 | 증거 파일과 촬영 시점 |
| 10 | 편차·자료 재사용·제외 사유·불확도/판정 방식의 해당 항목 | 근거와 검토 상태 |
| 11 | 검토·승인·서명·개정 이력 | 경로별 권한 및 발행 기록 |
| 12 | 경로별 제출 첨부자료 목록 | 매뉴얼·회로/블록도·라벨·신청 서류 등 |

이 순서와 공통 문서 구조는 설계 제안이며 FCC가 특정 서식으로 지정한 목차가 아니다. Certification과 SDoC에는 다른 요구가 있으므로 [항목별 근거표](report_field_map.csv)의 적용 조건에 따라 포함한다. RF 시험 보고서와 EMC 시험 보고서는 공통 표지·제품·방법·증거 구조를 공유하고, 시험별 결과 모듈을 선택한다. RF exposure/DFS 등은 해당 절차에 맞는 별도 결과 모듈을 추가한다.

## 측정 데이터의 보존과 표현

| 층 | 무엇을 보존하는가 | 바뀌면 안 되는 연결 |
|---|---|---|
| 원본 | 계측기 트레이스·CSV·바이너리·로그·사진·보정파일 | 파일 해시, 생성 장비/프로그램, 시각, 시험 실행 ID |
| 표준화 관측값 | 시간/주파수/위치 등 좌표, 측정량, 값, 단위, 실제 설정 참조 | 원본 파일 ID와 원본의 행/채널/인덱스 위치 |
| 계산 결과 | 입력 관측값, 적용 보정, 계산 방법/버전, 결과, 단위 | 모든 입력 및 보정/계산 근거 |
| 규정 판정 | 조건별 한계값·비교식·근거판본·유효성·판정 사유 | 판정 대상 결과와 한계값 정의 |
| 보고서 표시 | 선택한 결과·그림·설명·표시 반올림 | 표시값의 원래 계산 결과와 표시 규칙 |

단위는 값과 별도 필드에 저장한다. dB, dBm, dBµV, dBµV/m, W 등은 서로 다른 측정량으로 취급하며, 변환 조건·측정 임피던스·검출 방식 등 필요한 근거 없이 변환하지 않는다. 교정/보정이 장비 내부에서 적용됐는지 기록해 이중 보정을 막는다. 판정 전 반올림하지 않으며 표시 반올림은 별도 규칙으로 기록한다.

RF 전력, PSD, 점유대역폭, 대역외/불요방사, EMC 전도·복사방출 등은 각각 방법 프로필을 갖는다. 프로필에는 확인된 문서·조항, 필요한 입력/설정, 설정별 단위와 조건, 관측값 형식, 계산, 한계값, 유효성 검사, 필수 사진/로그, 보고 항목을 담는다. 실제 수치 설정은 표준 원문을 확인하기 전 빈칸으로 둔다.

## 빈 템플릿 사용 방법

[템플릿 폴더](../../templates/fcc/)와 [검토용 엑셀](../../exports/fcc_format_templates.xlsx)에 공통 구조의 빈 양식을 넣었다. 장비 제어 API나 완성된 LIMS DB 스키마가 아니라, 실제 기록으로 검토할 데이터 교환 초안이다.

- 각 ID는 고정 식별자다. `*_artifact_id`는 `artifacts`의 실제 증거 파일을 가리킨다.
- 한 프로젝트에 여러 제품 구성·방법·계획 항목·실행·결과가 연결될 수 있다. 복합기기의 동시동작 구성도 별도 `configuration`으로 식별한다.
- 복합 입력 목록·주파수별 한계곡선·상세 방법 설정은 JSON 등 별도 증거 파일로 연결한다. CSV 셀 안에 임의 구분자로 다중 값을 넣지 않는다.
- 비적용은 이유와 규정 근거를 요구한다. 측정 실패·누락·미확인은 비적용으로 변경하지 않는다.
- CSV는 헤더만 있으며 실측값·정답·합격 예시를 넣지 않았다. 필드의 뜻과 연결은 [데이터 사전](data_contract.csv)에 기록했다.

## 기존 자료의 역할

기존 자료는 보유하지만 현재 새 양식의 입력으로 제공된 상태는 아니다. 공개 규정 조사와 형식 설계는 계속 진행한다. 이후 기존 파일에서 새 형식으로 변환하는 매핑을 만들고 누락을 확인한다. 신규 수집부터 새 양식을 사용하고, 기존 원본은 보존한다. 과거 시험은 당시 적용판으로 재현하며 현행판 재평가와 구별한다. 기존 보고서와의 일치만으로 규정 적합성을 확정하지 않고 독립 재계산·방법 검토를 병행한다.

## 이번 형식의 한계와 다음 검토

§2.1033(b)의 Part 11/15/18 Certification 보고·첨부 요구, §2.938(b)의 SDoC 기록 요구, §2.947의 방법 식별·장비·복합기기·시험별 입증 요구를 구분해 공통 필드를 만들었다. 면허 무선의 §2.1033(c) 전체 요구, RF exposure, 각 KDB와 표준의 상세 요구는 개별 모듈에서 추가 확인해야 한다. 템플릿에 값이 들어갔다는 이유만으로 자동 승인하거나 정식 성적서를 발행하지 않는다.
