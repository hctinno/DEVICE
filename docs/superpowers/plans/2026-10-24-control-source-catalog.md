4. 개발4: 고정 DTO로 신규 모델·화면/HTTP 경로의 의미 있는 검사를 먼저 RED로 만들고 구현한다. 기존 UI 경계 회귀를 확인한다. API 원격 SHA를 인수한 뒤 실제 GET→선택→근거·모바일 브라우저를 검사하고 자기 브랜치에 게시한다.
5. 총괄: 담당별 수정/리뷰 결과를 적용하고 실제 API/화면/기존 접수 통합·소스 불변·DB 무변경을 확인한다. 현재 완료된 replay helper의 공통 hook 및 frequency source/actual spectrum browser를 같은 공통본에 연결한다. 새 관련/전체 검증 수와 과거 수를 섞지 않는다.
