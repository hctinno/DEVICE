# HCT FCC 사례 021/024 실행 계획

설계는 [공통 계약](../specs/2026-10-24-hct-fcc-case-catalog-design.md), 수집은 [실제 요청012](../../material-intake/2026-10-24-hct-fcc-corpus-request.md)를 따른다. 기존 PREPARE004/HARNESS016/E3632A019/UI017의 코드·수정·실패·원격 커밋을 보존한다.

1. 총괄: 신규 지시 전체 SHA와 로컬 head/미커밋 소유 파일을 기록한다. P01에 012를 실제 요청하고 수집1~8 실제 작업/ACK와 첫 B001을 인수한다. 모집단/확보/중복/미확보/단계별 미산정은 구분한다.
2. 개발1: PREPARE004 최종 검토를 유지하며 새 `codex/dev1-fcc-case-catalog021-20261024`에서 소유3파일로 021 usage의 정확 schema/DTO/예산/오류를 먼저 고정해 총괄과 개발4에 전달한다. 빠른 builder 검토 후 missing module·실패 경계 RED→읽기 인덱스/원본·페이지 검증/조회·접수 연결 GREEN을 구현한다. 기존 추출/Store 수정은 없다.
3. 개발4: UI017 독립 Yes/총괄 통합 기준을 보존하고 새 `codex/dev4-fcc-case-view024-20261024`의 소유5파일로 021 DTO와 일치하는 검증/DOM/브라우저 도구를 구현한다. 021이 아직 없을 때는 합성 contract fixture로 개발하고 실제 연결 수치를 따로 둔다. 둘 다 준비되면 private B001 실제 producer를 같은 도구로 연결한다.
4. 개발2/3: 현재 016/019를 구현·검증·소유게시한 뒤 corpus022 근거 검색/그룹 분할 평가와 corpus023 검토 방법의 설정/계산·가상 연결을 별도 작은 계약으로 받는다. 전체 수집 완료를 기다리거나 원본 수치로 합성 파형을 실측처럼 만들지 않는다.
5. 각 owner: 관련 검사와 실패/수정·실제 배치 증거를 private에 보존하고 자기 변경만 커밋·푸시/원격 대조한다. 총괄은 독립 리뷰를 배정하고 Important/Critical을 소유 수정 후 재검토한다.
6. 총괄: 승인된 기능만 정확 커밋으로 통합한다. 새 기능에 맞는 검사·실제 API/브라우저·기존 접수/장비/DUT 회귀·문서 무결성/UTF-8/링크/해시를 실행하고 근거·한계를 통합 영수증/후속 대장에 갱신한다. 개발 브랜치 커밋/푸시·원격 일치와 깨끗한 상태를 확인한 뒤 다음 작은 단위를 실제 배정한다.

첫 단위 완료는 검수된 사례를 페이지 근거와 함께 조회하고 잘못된 제품/방법 연결을 거절하는 소프트웨어 기능의 확인이다. 전수 수집·전체 분석·법적 요구 승인·실제 AI 독립 평가·실물/현장 자동화 완료와 별개다. 현재 사용자 결정·준비 필요 항목은 0이다.
