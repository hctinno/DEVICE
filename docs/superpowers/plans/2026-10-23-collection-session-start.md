# 메인 총괄과 수집1~수집8 시작 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 이 계획은 문서와 운영 인계에 한정한다. 사용자가 세션을 생성하고 수집자는 Git을 사용하지 않는다는 아래 제약이 일반 개발 절차보다 우선한다.

**Goal:** 사용자가 GitHub 지시문을 메인에게 한 번 전달하면 메인이 수집1~수집8의 지시·진행·취합·게시를 맡도록 실행 계약을 준비한다.

**Architecture:** 기존 수집자가 수집1(S01)이 되고 사용자가 수집2~수집8과 메인을 연다. 메인(P01)은 자기 환경의 실제 세션 제어 도구로 각 수집자를 식별·지시하고 로컬 고정 사본·배정·인수·Git 게시도 맡는다. 현재 클라우드 담당은 지시 문서를 GitHub에 준비하고 파이프라인 개발을 계속하며 사용자 PC의 세션을 직접 제어하지 않는다.

**Tech Stack:** 기존 Markdown/CSV/JSON, 로컬 파일, P01 전용 Git, 기존 Python 패키지 인수기. 새 제품 코드·서비스·의존성은 추가하지 않는다.

**Spec:** [FCC 병렬 수집 운영 설계](../specs/2026-10-23-fcc-parallel-collection-design.md)

## Global Constraints

- 이름은 `수집1`~`수집8`, ID는 S01~S08, 자기 작성 폴더는 `.local/collection/s01/`~`s08/`이다.
- 기존 수집자가 수집1이며 이전 원본·진행 요청·폴더를 보존한다.
- 수집자는 Git 명령을 하지 않는다. 같은 로컬 프로젝트의 Git은 P01만 조작한다.
- 지시와 배정은 고정 사본을 사용한다. 실제 경로·기존 진행 상태는 P01이 로컬에서 확인한다.
- ready와 게시 배치는 수정하지 않는다. 정정은 새 ID로 반환한다.
- 별도 대화를 내부 하위 에이전트로 임의 대체하지 않는다. 도구 유무는 메인이 자신의 환경에서 확인한다.

## Review Focus

- 기존 수집의 EMC/SAR/장비 작업이 새 담당과 중복되지 않도록 legacy 예약을 먼저 만든다.
- GitHub 문서/공유 파일 작성을 실제 메시지 전달·멈춘 세션 재실행으로 오인하지 않는다. 메인은 실제 도구 결과와 응답을 확인한다.
- 과거 DRAFT 지시나 수집자 Git 지시가 새 세션에 적용되지 않게 고정 버전을 확인한다.
- 같은 프로젝트의 기존 사용자 변경과 실행 중 파일을 게시에 섞지 않는다.
- 비공개 경로가 담긴 legacy 목록은 로컬에 두고 공개 배치의 내용·권리를 별도로 확인한다.

## Task 1: 역할 확정과 전달 문서

**Files:** `handoff/parallel/MAIN_AGENT_PROMPT.md`, `README.md`, `S01.md`~`S08.md`, `P01.md`, `START_HERE.md`; 루트 인계 문서·인계 ZIP/해시.

**Interfaces:** 입력은 사용자 확정 이름/기존 수집1 결정, 출력은 역할표·시작 문장과 고정 지시용 커밋이다.

- [x] 역할표·상태·기존 수집1 매핑과 메인 총괄 지시, 메인에게 한 번 전달할 문장을 작성한다.
- [x] 인계 문서의 과거 승인 대기 문구를 역할 확정/로컬 준비·지시 전달 미확인으로 갱신한다.
- [ ] `python scripts/check_artifacts.py`, 변경 문서 로컬 링크, 인계 ZIP/해시와 역할 ID 매핑을 확인한다. 문서 변경이므로 제품 단위 테스트를 새로 작성하지 않는다.
- [ ] 명시한 문서/스냅샷만 커밋·푸시하고 원격 SHA를 확인한다.

## Task 2: 메인(P01)의 세션 식별·로컬 준비·첫 배정

**Files:** 로컬 `.local/collection/s01/legacy-inventory.md`, `briefs/<sha>/`, `control/<version>/`, `START.md`.

**Interfaces:** 입력은 Task 1 커밋·실제 프로젝트/세션·기존 수집 상태, 출력은 실제 세션 ID 매핑·제어 기능 확인·고정 지시·예약/배정·START와 각 세션의 작업 수신 확인이다.

- [ ] 메인 환경의 실제 도구로 같은 프로젝트의 수집1~수집8을 식별한다. 지시 전달/새 턴 실행 기능이 없으면 전송 성공을 기록하지 않고 메인에서 한 번만 한계와 연동 방법을 보고한다.
- [ ] 수집1의 기존 확보/진행 요청과 Git 금지 적용을 확인하고 미확인 범위는 예약한다.
- [ ] 기존 작업 트리를 전환하지 않고 확정 커밋의 사본을 준비해 파일 해시를 확인한다.
- [ ] 중복 없는 초기 요청 배정을 만들어 실제 경로·지시 SHA·배정 버전을 START에 기록한다.
- [ ] 수집1~수집8이 자기 사본·자기 작성 폴더만 쓰는지 시작 보고로 확인한다.
- [ ] 실제 task ID·시도 번호·배정 버전·요청 범위를 채워 각 세션에 지시하고 응답을 확인한다. 상태 조회와 파일 작성만으로 실행을 확인한 것으로 보지 않는다.

## Task 3: 첫 완료 배치 인계

**Files:** 수집자 `work/ready`, P01 `snapshots/receipts`, 공개 가능한 `materials/packages/`, `manifests/`, `collection/`.

**Interfaces:** 입력은 동결한 로컬 배치, 출력은 검사된 패키지·게시 SHA·클라우드 인수 가능 자료다.

- [ ] P01은 파일이 닫힌 ready만 복사하고 파일 목록·크기·해시·경로를 대조한다.
- [ ] 기존 배치와 함께 인수해 문서/배치 ID 충돌을 검사하고 공개 가능한 자료만 패키징한다.
- [ ] 완성 파일만 명시해 게시하고 원격 SHA·receipt를 기록한다. 실패 시 원래 ready는 유지한다.
- [ ] 완료한 세션에 다음 배치를 보내고 실패/정정은 메인이 취합한다. 응답 지연만으로 같은 작업을 중복 재배정하지 않는다.

Task 2~3의 로컬 실행은 현재 클라우드에서 완료했다고 보고하지 않는다. 역할 승인은 완료됐으므로 다시 승인받지 않고, 실제 로컬 준비와 자료 확보 증거로 진행 상태를 갱신한다.
