**Goal:** 원본 SHA-256과 페이지별 텍스트·줄 위치를 보존하는 PDF/UTF-8 추출기를 만든다.

**Architecture:** 바이트와 파일 이름을 받는 독립 함수가 JSON 호환 결과를 반환한다. UTF-8은 표준 라이브러리, PDF는 버전 고정 pypdf를 사용한다. 원본과 추출 텍스트의 hash를 분리하며 기존 접수/DB 계약은 변경하지 않는다.

**Tech Stack:** Python 3.12, unittest, pypdf 6.21.2, 기존 reportlab(합성 PDF 검사).

## Review Focus

- 한국어·BOM·CRLF·빈 줄: 원본 hash와 텍스트 줄 참조를 혼동하지 않아야 한다.
- 텍스트/이미지가 섞인 PDF: 읽은 페이지를 보존하고 미해석 페이지를 드러내야 한다.
- 정확히 한도와 한도+1 입력: 부분 상태와 보존 텍스트를 일관되게 반환해야 한다.
- 암호/손상/미지원/의존성 부재: 결과에서 이유를 구별하고 파서 복구를 성공으로 숨기지 않아야 한다.
- 인용 범위/추출 텍스트 변조: 잘못된 페이지·줄 또는 hash가 다른 텍스트를 인용하지 않아야 한다.

## 선택과 기록

- 이미 배정된 수용 조건에 따라 별도 시작 승인 없이 실행한다. 새 설계 승인 절차나 하위 세션은 만들지 않는다.
- `extract_document(payload: bytes, filename: str, *, limits: ExtractionLimits | None = None) -> dict`를 제공한다.
- `page_citation(result: dict, page_number: int, line_start: int, line_end: int) -> dict`로 페이지 지역 줄 인용을 반환한다. 기존 분석기의 인용과 자동 호환시키지 않는다.
- 기본 한도는 입력 16 MiB, PDF 200페이지, 보존 텍스트 1,000,000문자, 페이지 내용 스트림 8 MiB다. 파서 실행 시간·메모리의 OS 수준 제한을 보장하지 않는다.
- PDF는 strict 모드로 읽는다. 이미지 전용 페이지는 OCR 필요로, 다른 비어 있지 않은 무문자 페이지는 no_text로 구별한다. 표/배치의 의미 정확도는 보장하지 않는다.
- 완전 추출 `ok`, 빈 입력/문서 `empty`, 혼합/한도 중단 `partial`과 별도 실패 상태를 사용한다. 인용 hash는 추출 텍스트에 대한 hash다.
- 실행 ledger는 `.local/DEV1-DOC-001/progress.md`로 둔다. 기존 사용자 설정이나 공통 ignore 파일을 바꾸지 않는다.
