# DEV2-WORKER-001 제한된 접수 작업자 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. 이번 배정은 이 세션에서 직접 구현하며 하위 에이전트를 생성하지 않는다.

**Goal:** 현재 접수 작업을 제한된 횟수/시간 동안 인수하고 합성 분석 제공자의 응답을 기존 계약으로 검증·완료하거나 실패 처리한다.

**Architecture:** `claim_job` → 별도 spawn 프로세스의 제공자 → `complete_job`/`fail_job`을 연결한다. 부모만 DB와 임대 토큰을 보유한다. 스레드 시간 초과는 실제 계산을 중단하지 못하므로 사용하지 않고, 종료 가능한 동기 제공자 프로세스를 사용한다.

**Tech Stack:** Python 3.12 표준 라이브러리, SQLite, unittest. 추가 의존성 없음.

**Spec:** [DEV-SPRINT-001](../../../handoff/development/SPRINT-001.md)의 DEV2-WORKER-001 절.

## Review Focus

- 실제 접수와 합성 제공자 불일치: 원자적 `synthetic_only=True` 인수, 구버전 사전 거절, 제공자 호출 금지.
- 프로세스가 늦게 반환한 응답: 실제 종료 및 마감 후 응답 불인정.
- 보완/경쟁 인수: 현재 token·revision이 아닌 작업에 DB 쓰기 금지.
- 비정상 제공자: 예외 내용·출력·임대 토큰의 노출 방지, 잘못된 producer·인용·과대 출력 거절.
- 무한 실행 요청: 횟수 또는 시간 한도 필수, 시간 종료와 정리 구간 구분.

## 구현 선택과 공통 계약의 한계

스레드와 협조적 취소만으로는 무한 대기 제공자를 종료할 수 없다. spawn 프로세스 및 제한된 JSON 결과 파일을 사용하고, 프로세스가 종료된 뒤에만 응답을 읽는다. pipe의 큰 응답 전송이 부모를 무기한 막는 경로를 피한다. 정리 구간은 terminate/kill 각각 짧은 한도만 기다리며, 종료 확인에 실패하면 추가 작업을 인수하지 않는다. 전체 실행 시간은 새 인수와 제공자 실행의 마감이며 DB 트랜잭션/OS 프로세스 정리 시간까지의 실시간 보장은 아니다.

총괄이 공통 `claim_job`에 `synthetic_only: bool = False`를 추가한다. 합성 작업자는 반드시 `synthetic_only=True`를 전달하며, 이 키워드가 없는 구버전에서는 인수 전에 설정 오류를 낸다. 실접수를 먼저 인수했다가 `fail_job`으로 반납하는 우회는 금지한다. 총괄의 검증된 SHA를 받은 뒤 이 공통 변경을 인수한다.
