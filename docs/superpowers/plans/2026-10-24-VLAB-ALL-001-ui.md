# VLAB-ALL-001 개발4 — 가상 시험소 화면 실행 계획

기준일: 2026-10-24, Asia/Seoul. 총괄이 배정한 전체 Un-licensed 가상화의 UI 단위다. 원시데이터 추가 확보는 선행조건이 아니다.

## 범위와 계약

- 기존 접수 화면·서버, Store, 가상 장비 모듈과 실행 중인 데모를 변경하지 않는다.
- `labflow/virtual_fleet_server.py`, `frontend/virtual_fleet/`, 전용 서버 검사·사용법만 구현한다. 현재 독립 개발 브랜치에서 작업한다.
- `create_server(runtime, *, catalog, topology, role_actions, host='127.0.0.1', port=8770)`에 신뢰된 순수 가상 runtime을 주입한다.
- runtime의 `execute(request_id, device_id, action, parameters=None)`, `advance(request_id, ticks=1)`, `observations()`, `coverage()`만 호출한다. 작성자 고장 제어는 HTTP에 노출하지 않는다.
- `GET /api/state`, `POST /api/actions`, `POST /api/advance`를 제공한다. 변경은 정확한 same-origin·CSRF·엄격한 JSON·선언된 action/parameter·요청 ID 검사 후 직렬 실행한다.
- catalog 전체와 배치된 장비 수를 구별하고 토폴로지, 모든 장비 상태·관측·동작·가상 tick·설정 revision·지원 한계·근거를 표시한다. 관측은 합성/실장비 미검증 표시를 유지한다.
- 최초 로딩·오류·빈 토폴로지를 구분한다. 새 응답의 검증·렌더를 완료한 뒤 화면 상태를 함께 게시한다. 변경 영수증과 후속 새로고침 오류를 분리한다.

## 실행 단위

1. 서버 경계 검사를 먼저 실패시킨다. 주입 runtime, loopback/Host/Origin/CSRF, 요청 형식·상한·중복/충돌, 동시 요청과 오류 후 복구를 검증하고 서버를 구현한다.
2. 합성 전용 fixture와 상태 검증·동작 인수 변환 검사를 먼저 작성한다. 일반 catalog/role schema를 소비하는 standalone 화면을 구현한다. fixture는 실제 모델 전체 완료의 근거가 아니다.
3. 브라우저에서 토폴로지 선택, 역할별 동작, pending→advance→완료, 설정 변경 후 무효, 오류 후 복구, 첫 로딩 실패, 마지막 성공 화면 보존, 모바일·키보드·XSS 경계를 검증한다. 새 통합 runtime이 준비되면 총괄과 별도 대조한다.
4. Python 전체 회귀, Node/브라우저 검사, 정적 검사, 문서 무결성 검사를 실행한다. 자기 브랜치에 커밋·푸시하고 SHA/API/검증과 남은 통합 작업을 총괄에게 보고한다.

## 검토 초점과 한계

정상 결과만으로 모델 전체 지원·실장비 정확도를 주장하지 않는다. 조회 중 runtime 오류와 잘못된 schema를 빈 성공으로 바꾸지 않는다. 요청 중복은 같은 내용을 재실행하지 않으며 충돌은 거절한다. 응답 유실 시 같은 요청 ID로 재시도할 수 있어야 한다. 서버 재시작 이후 중복 억제는 영속 보장이 아니다. API는 시뮬레이션 전용이며 파일·실장비 주소·암호 입력과 작성자 제어를 받지 않는다.

별도 에이전트 생성 없이 구현자가 독립 검토 패스를 수행하고 총괄의 통합 리뷰를 받는다. 사용자 지시의 연락 경계를 따른다.

## 실행 기록

- 시작: 기존 HEAD `3f495b830cb464217659ee4c7def96ab562bec18`, 작업 트리 깨끗함. 총괄의 core/integration 파일은 아직 없어 합의된 public 계약의 합성 대역으로 시작한다.
- Task 1: 서버 경계 RED→GREEN. 신규 모듈 부재, 숫자 overflow, 비ASCII CSRF, 가상 포트 선택, 잘못된 노드 envelope/coverage를 실패시킨 뒤 수정했다. 호출 중 예외는 요청 ID를 보존하며, oversize body는 Windows 연결 초기화가 정상 413 응답을 가리지 않도록 제한된 양만 비운다.
- Task 2: fixture/model RED→GREEN. 합성 전원/환경/DUT/RF경로/측정의 pending→tick→완료, 설정 변경 무효화, 복구를 검사했다. 운영자 동작/인수는 고정 role schema에서 생성한다.
- Task 3: 브라우저 RED→GREEN 13개. 시각·모바일·키보드, 응답 유실 재시도와 오류 복구를 확인했다. 별도 렌더 예외로 조회 시각과 DOM이 일부만 갱신되던 것을 재현하고 게시 전에 시각 형식화까지 완료하도록 고쳤다. 총괄 catalog 64개 전체 조회/선택/구분도 확인했으며 이 검사에서 실제 role 동작 실행은 0이다.
- Task 4: 전체 Python 131개, 별도 fixture 3개, 전체 Node 26개, 신규 브라우저 13개, 기존 접수 브라우저 19개 통과. 기존 접수 데모 8765/8766은 최초 접속 거절이었으므로 새 합성 fixture/임시 포트로만 회귀를 수행했다. 기존 프로세스·데이터·기존 소스 변경 없음. 기본 문서 검사와 신규 문서 2개의 UTF-8/링크 검사, JS/Python 정적 검사와 diff 검사를 수행했다.
- Final review: self-review (하위 에이전트 생성은 사용자 지시로 금지). 서버/운영자 경계, 상태 원자 게시, 프로필 전체 조회와 검사 범위를 별도로 대조했다. 남은 공유 runtime/역할 통합은 총괄 리뷰에서 수행하며 이 UI fixture를 전체 장비 완료로 처리하지 않는다.
