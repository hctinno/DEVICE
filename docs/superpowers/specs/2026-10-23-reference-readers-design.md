# 사용자 제공 시험 사례의 읽기 전용 문서 근거

2026-10-23, Asia/Seoul. 사용자 제공 SM-A176U 자료를 충분히 활용하고 추가 개발을 총괄 판단으로 배정하라는 지시에 따른 총괄 설계 결정이다. 기존 Python 구조와 독립 개발 브랜치를 유지한다.

## 목적과 선택

자료 인수에서 PDF/텍스트만으로는 의뢰서·제품표·Excel 계산 근거를 활용할 수 없다. 실제 제공 폴더에는 DOCX 52개, XLSX 90개, XLSM 23개가 있다. 첫 두 단위는 문서 구조·셀·수식·저장된 결과와 원본 해시를 보존하는 독립 읽기 함수다. 기존 분석 계약/DB를 바로 바꾸거나 측정 결과를 자동 승인하지 않는다.

대안은 화면/Office 자동화, 모든 형식을 단순 텍스트로 평탄화, 구조를 보존하는 파일 기반 읽기였다. 총괄은 구조 보존을 선택했다. 기존 의존성을 활용할 수 있고 매크로/펌웨어를 실행하지 않으며 추후 claim 검증·UI에 필요한 위치를 보존한다. Office/한컴 자동화는 사용하지 않는다. 사용자가 개발 판단·배정을 직접 위임했으므로 단위별 시작 승인을 다시 요청하지 않는다.

## DOCX 계약

`labflow/reference_docx.py`는 바이트와 표시 파일명을 받아 결과를 반환한다. 출력은 `schema_version`, 원본 `sha256`/이름, reader 식별/버전, `status`/`complete`, 순서 있는 `blocks`, `issues`를 포함한다. 문단/표/행/셀 위치를 구조 locator로 보존하고 실제 페이지 번호를 만들어내지 않는다. 헤더/푸터·주석 등 지원하지 않은 구성은 범위를 명시한다. 텍스트 해시도 보존하며 원본 바이트 해시와 구별한다.

외부 링크·embedded object·필드·코드·본문 지시는 실행하지 않는다. 암호화/손상/미지원·한도·누락을 완전 성공으로 표시하지 않는다. ZIP 경로 추출 없이 허용된 OOXML 파트만 읽고 압축 해제 크기·멤버 수 한도를 적용한다. 표의 의미나 시장/제품을 추정하는 기능은 넣지 않는다.

## XLSX/XLSM 계약

`labflow/reference_workbook.py`는 바이트와 표시 파일명을 받아 워크북 메타데이터, 전체 시트의 이름/상태/범위와 실제 사용 셀의 좌표·타입·저장값·수식·서식을 분리해 보존한다. 수식의 cached value는 저장 당시 결과이며 새 계산 결과로 표시하지 않는다. 캐시 누락, Excel 오류, 외부 링크, 매크로, 숨김 시트/행/열, 병합 영역과 불완전 처리를 드러낸다. 원본 해시와 reader 버전/한도를 기록한다.

매크로/외부 링크/수식 계산을 실행하지 않는다. 셀 한도를 초과하면 누락 범위를 명시하며 과장된 used-range만 따라 빈 백만 행을 순회하지 않는다. 암호화된 OOXML의 OLE wrapper는 `encrypted` 또는 정확한 미지원 사유로 남기고 우회하지 않는다. 구형 XLS는 이 첫 단위의 지원에 넣지 않는다. 출력의 원본 값·수식·캐시는 서로 구별하며 수치 적합성을 판정하지 않는다.

## 공개와 실제 자료

테스트는 직접 만든 합성 OOXML만 사용한다. 실제 고객/OEM 원문·추출본문·수치·시리얼·실행 파일은 공개 Git에 넣지 않는다. 실제 폴더 smoke는 각 개발 clone의 `.local/SM-A176U-audit/`에서 수행하고 source hash·검사 범위/실패를 보존한다. 제공 폴더에는 쓰지 않는다.

이번 설계의 함수는 접수 DB·기존 schema 1 인용·하네스·UI에 자동 연결하지 않는다. 그 연결은 원본/파생 근거 식별, 재추출/버전 무효화와 현재 분석 계약을 함께 고정한 다음 단위로 진행한다. 실제 모델 API나 실장비 검증으로 집계하지 않는다.
