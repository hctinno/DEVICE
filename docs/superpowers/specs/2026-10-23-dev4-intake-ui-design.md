# DEV4-UI-001 접수 조회 화면 설계

2026-10-23 (Asia/Seoul). 기준: [작업 배정](../../../handoff/development/DEV4-UI-001.md), [화면 규칙](../../../DESIGN.md), [접수 계약](../../fcc/active_intake_usage.md).

## 의도와 경계

현장 사용자가 Codex/CLI 없이 현재 접수의 근거와 다음 조건을 읽는 첫 로컬 브라우저 화면이다. 목록 → 상세 → 사실/출처·누락/충돌 → 작업/알림을 연결한다. 업로드, 답변, 보류 변경, 가상/실장비 실행은 이 단위의 동작 버튼으로 제공하지 않는다. 기존 접수 업무와 전체 시험소 목표를 조회 화면의 완성으로 대체하지 않는다.

사용자는 기술 선택과 작은 구현을 개발4에 위임했다. 아래 선택은 개발4의 구현 판단이며 별도 제품 범위 승인으로 기록하지 않는다. 독립 clone과 지정 브랜치만 변경하며 하위 에이전트를 사용하지 않는다.

## 접근안과 선택

- 선택: HTML/CSS/ES module + Python 표준 라이브러리 서버. 기존 Python 서비스에 작은 읽기 어댑터를 연결하고 설치/빌드 없이 실행한다. DOM 텍스트 API로 모든 원문을 표시한다.
- 검토: React/Vite + 별도 API. 확장성은 있으나 현재 조회 범위에는 빌드·패키지 의존성이 더 많다.
- 검토: 서버 HTML만 렌더링. 단순하지만 목록 필터·상세 전환·새로고침 오류와 포커스 관리에는 클라이언트 모듈이 적합하다.

## 구성과 계약

- `labflow/ui_read_model.py`: `intake_status`, `notifications`를 같은 SQLite 읽기 스냅샷에서 호출한다. `Store` 생성자가 스키마/디렉터리를 변경하므로 서버에서 생성하지 않는다. `mode=ro`, `query_only` 연결만 제공한다. 없는 저장소는 생성하지 않고 읽기 오류로 반환한다.
- `labflow/ui_server.py`: `127.0.0.1`만 바인딩한다. 정적 파일은 고정 allowlist, API는 `GET /api/intakes`, `GET /api/intakes/{id}`다. 요청으로 파일 경로/SQL을 받지 않고 변경 메서드를 거절한다. Host/Origin 검사와 CSP, no-store를 사용한다. 기본 라이브러리의 개발용 로컬 서버이며 외부 배포용 인증 서비스가 아니다.
- 목록 JSON: `schema_version`, `generated_at`, `intakes`, `notifications`. 상세 JSON: `schema_version`, `generated_at`, `intake`, 해당 접수의 `notifications`. 원래 서비스 필드/열거형은 보존한다. 작업 lease token·worker 비밀값을 추가하지 않는다.
- `frontend/`: 고정 셸, 반응형 토큰/CSS, 상태·포맷 모듈과 DOM 렌더링. 데이터는 same-origin API만 사용한다. 원문/오류를 `innerHTML`로 삽입하지 않는다. 외부 리소스를 요청하지 않는다.
- `frontend/demo_fixture.py`: 기존 접수 함수로 새 전용 합성 workspace를 생성한다. 기존 디렉터리 덮어쓰기를 거절한다. 빈 저장소와 대기/실행 중/실패/보류/충돌/근거 부족/준비 후보를 재현한다. 자동 AI 실행이나 실측이 아니다.

## 화면과 상태

네이비 왼쪽 탐색, 밝은 스틸 배경, 블루/시안 강조를 사용한다. Pretendard가 설치되어 있으면 우선 사용하고 시스템 한글 글꼴로 폴백한다. 출처·상태는 색과 텍스트를 함께 표시한다. 목록 검색·상태 필터·수동 새로고침을 제공한다.

상단에 조회 모드·최종 조회 시각, 목록에는 실제 건수와 접수별 합성 여부를 표시한다. 상세의 첫 정보는 접수 ID·버전·위임/보류·실측 지원 미검증이다. 접수 자료가 없는 상태, 데이터 로딩, 서버 읽기 실패, 필터 결과 없음은 서로 다른 메시지다. 알 수 없는 상태는 원래 코드와 지원 미확인을 표시한다.

확정/추론/불확실/사용자 답변을 구분하고 각 사실에 제출 분석의 해당 후보 인용을 연결한다. 사용자 답변은 event ID로 표시하며 다른 출처의 인용을 붙이지 않는다. 충돌 후보와 불확실 사실도 원문과 함께 볼 수 있다. 인용이 없으면 근거 없음으로 표시한다. 해석기 미지원 파일, revision별 원본 hash/크기, 이전 작업 상태를 보존한다.

알림은 저장된 로컬 기록이다. 읽음·미읽음·발송 완료를 추정하지 않는다. 과거 revision의 알림은 과거 기록으로 명시한다. `prepare_plan`은 계획 연결 대기이며 시험 준비 완료가 아니다. `completed` 작업은 분석 작업 완료일 뿐 시험 완료가 아니다.

## 검증과 남은 계약

실제 접수 API/SQLite로 생성한 합성 fixture에서 일관성·읽기 부작용 없음·위험 HTML 표시·미지 상태·오류·필터/이동을 검사한다. 실제 브라우저에서 빈 상태·합성 상세·작은 화면을 확인한다. 문서 무결성, Python 정적 컴파일과 관련 회귀 검사를 별도로 수행한다.

공통 모듈 변경 없이 조회가 가능하다. 알림 전달 확인·답변 쓰기·서버 인증·실시간 이벤트·모델/가상 실행 연결·원본 바이너리 뷰어는 후속 계약이다. 원본 내용 검증은 기존 접수 분석 계약에서 수행하며 이 조회는 저장된 출처/인용과 hash를 표시한다. 조회만으로 원본의 현재 무결성·AI 의미 해석·현장 준비를 새로 인증하지 않는다.
