# 스마트폰 2.4 GHz Wi-Fi b/g/n — FCC §15.247 AI 시험 파이프라인

작성일: 2026-10-23 (Asia/Seoul). 상태: 사용자 요구를 반영한 **설계 검토안**. 이 문서의 기능이 구현되었거나 실측 검증되었다는 뜻이 아니다.

## 1. 이번에 만드는 것

사용자가 제조사의 신청서·시험의뢰서·제품 자료를 지정 폴더에 넣으면 AI가 제품을 이해하고 필요한 시험·자료·장비를 안내한다. 누락과 충돌을 해결한 뒤, 사용자는 AI의 안내에 따라 시료·케이블·장비를 물리적으로 연결한다. AI는 연결 상태와 시험모드를 확인하고 스마트폰 및 계측기를 제어하여 시험·원시 데이터 저장·계산·성적서 작성·리뷰를 진행한다. 중간에 연결 변경이나 추가 정보가 필요하면 해당 작업을 요청하고 완료 후 이어간다.

### 사용자가 정한 범위

- 대상은 스마트폰의 **2.4 GHz IEEE 802.11b/g/n**, 규정은 **FCC §15.247**을 중심으로 한 해당 RF 시험 범위다.
- 제조사에서 시험용 펌웨어와 RF 시험모드 제어도구를 제공받을 수 있다. 개별 제조사·모델·버전의 실제 도구는 아직 제공되지 않았다.
- 물리 연결·교체·시료 배치는 사용자가 수행한다. AI는 필요한 작업과 확인 방법을 안내하고 소프트웨어 제어·측정·문서화를 수행한다.
- 안테나 이득, 출력 설정 문서, Power Target 등이 빠졌으면 무엇이 필요한지와 무엇이 진행되지 못하는지를 알려준다.
- 시험방법에 맞는 새 원시 데이터 구조와 성적서 포맷을 만들며, 기존 양식에 얽매이지 않는다. 기존 자료는 후속 독립 검증에 사용한다.
- 현재 에이전트는 기획·구현을 맡고 별도 에이전트는 원문·매뉴얼 등 자료 준비만 맡는다. GitHub로 인계한다.

스마트폰 전체의 셀룰러·Bluetooth·5/6 GHz Wi-Fi·UWB 시험, KC/EU 확장, 시료 운반 로봇, 자동 배선, 인증 포털 제출은 이번 구현의 선행조건이 아니다. 장기 목표는 유지하되 이 버전의 완료율에 섞지 않는다. 명칭은 **사람이 연결을 지원하는 AI 시험 자동화 v1**로 표시한다.

§15.247(i)의 RF exposure 같은 연관 의무는 누락하지 않고 별도 근거의 인수·연결 대상으로 관리한다. SAR 측정기 자체의 자동화는 이번 범위 밖이다. 이 RF 모듈의 보고서 완료와 스마트폰 전체 FCC 인증 준비 완료를 구분한다.

## 2. 접근 방식과 설계자의 제안

사용자가 선택한 업무 방식은 **폴더 접수 → AI 자료검토 → 사용자 연결 → AI 시험·성적서·리뷰**다. 기존 Python/SQLite 코어와 MCP를 확장해 이 한 흐름을 먼저 구현하는 것을 제안한다.

| 구현 접근 | 장점과 필요한 조건 | 이번 설계에서의 취급 |
|---|---|---|
| 공통 시험건·실행 절차에 제조사 도구와 계측기 어댑터 연결 | 제품 정보·측정·보고서의 근거 연결을 직접 관리할 수 있다. 실제 장비별 연결 검증이 필요하다. | 기존 코어를 활용하는 권장 기본안. 세부 기술 선택은 설계자의 제안이다. |
| 기존 시험 자동화 SW를 실행 엔진으로 사용 | 검증된 측정 기능을 재사용할 수 있다. 공식 API, 조건 설정, 원시 파일·실행 로그 접근이 필요하다. | 해당 SW가 확인되면 공통 실행 계약의 어댑터로 사용한다. 전체 설계가 특정 SW 확보에 종속되지는 않는다. |

AI가 제안한 계획은 구조화된 실행 절차로 검사한다. 측정 때마다 새 명령·한계값·공식을 즉흥 생성하지 않는다. 통과한 방법·어댑터·계산 버전으로 실행하고, AI는 계획·예외 설명·문서 해석과 리뷰를 담당한다.

첫 사용자 인터페이스는 AI 대화, 작업 상태, 연결 안내서 및 로컬 보고서다. 별도 대형 웹 서비스나 로봇 제어 제품을 먼저 만들지 않는다. 원본과 업무 상태는 하나의 시험건 ID로 연결한다.

첫 버전의 운영 주체로 **현장 PC의 상시 업무 서비스**를 제안한다. 폴더 감시기가 새 자료 이벤트를, 대화/상태 화면이 사용자 응답 이벤트를 만들고, 서비스가 이를 영속 작업 큐에 저장해 AI 작업자를 호출한다. AI 작업자는 설정된 모델 API와 MCP를 사용하며 대화 이력 자체가 아닌 DB의 시험건 상태에서 재개한다. 개발 중 Codex에서 같은 동작을 수동 호출할 수 있으나, 운영 기능의 완료 조건은 Codex 대화창을 열어 두는 것에 의존하지 않는다. 별도 ChatGPT/Codex 구독만으로 이 서비스의 모델 API 사용 권한까지 있다고 가정하지 않으며, 실제 공급자·자격증명·데이터 처리 조건은 배포 설정으로 관리한다.

중복 파일 이벤트·응답은 같은 작업을 중복 실행하지 않게 식별한다. AI 작업자가 종료되거나 모델 API가 응답하지 않으면 상태와 대기 작업을 보존한다. 재시작 때 미완료 작업을 확인해 재개하되, 실제 RF 동작은 현장 실행기의 잠금·제한 시간·정지 정책과 상태 재확인을 따른다. 사용자 대화창 종료와 실제 제어 세션 단절은 별개 이벤트로 처리한다.

| 자료 접수 | 폴더의 새 파일·개정본을 식별하고 원본 보존, 문서 종류 분류 | 받은 파일·읽지 못한 파일·인식된 제품 목록 | 파일 처리 결과와 출처 기록 |

기본 상태는 `received → extracting → needs_information → plan_ready → needs_connection → preflight → running → calculating → reporting → reviewing → reviewed`로 두되, 작업별 보류·실패·중단 상태와 재개 위치를 별도로 저장한다. 단일 상태 문자열로 병렬 작업의 진행을 덮어쓰지 않는다.

누락 자료가 있으면 계획 초안과 독립적인 문서 처리는 계속한다. 송신이나 판정을 막는 누락은 해당 동작을 차단한다. 안테나 이득을 0으로 채우거나 Power Target을 규정 상한으로 대신하지 않는다.

## 4. 폴더 접수와 제품 사실

초기 입력 대상은 PDF, DOCX, XLSX/CSV, 일반 이미지와 텍스트다. 읽지 못한 파일은 이름·사유·필요한 변환 형식을 표시한다. 이미지와 스캔 PDF는 OCR 결과와 원본 위치를 함께 보존한다. 문서의 매크로·스크립트·명령문을 실행하지 않는다. HWP 또는 Hancom Office 실행은 기존 작업 규칙에 따라 수행하지 않는다.

폴더는 사용자가 지정한 입력 경로만 읽는다. 업로드/복사가 끝나지 않은 파일은 인수를 미루고, 동일 해시는 재처리하지 않는다. 출력 폴더를 입력으로 재감시하지 않으며 다른 위치를 가리키는 링크를 임의로 따라가지 않는다. 삭제·덮어쓰기가 원본 이력 삭제가 되지 않게 한다.

제품별로 `case_id`, 파일 해시와 인수 시각, 문서 판본, 제품·시료 식별자를 둔다. 다른 제품 자료가 함께 들어오면 분리하거나 확인 작업을 만든다. 입력 폴더·실측 결과는 현장/비공개 저장소에 두며 현재 공개 코드 저장소에는 고객 원본을 자동 커밋하지 않는다.

필수 사실 후보는 다음과 같다. 필수 여부는 해당 시험/단계별로 정한다.

| 묶음 | 추출·확인할 정보 |
|---|---|
| 제품 식별 | 신청자·제조사·모델/변형·시료 번호·HW/FW·미국향 동작 설정 |
| 무선 구성 | b/g/n, 지원 채널·주파수·대역폭, 데이터레이트/MCS, 송신 체인·안테나 수, MIMO/beamforming 지원과 실제 사용 구성 |
| 안테나·출력 | 안테나 형식·체인별 이득/근거, Tune-up/Power Target과 허용 범위·모드/채널별 조건, RF 포트/경로·출력 제어 설명 |
| 동작·전원 | 시험 신호·듀티·트리거, 충전 중 동작·충전기·USB/보조기기, 배터리 상태, 다른 송신기 상태와 동시 송신 정보 |
| 제어도구 | 제조사 도구명·버전·실행 환경·문서·실행 권한·지원 명령·로그, 호환 펌웨어와 종료/복구 절차 |

사용자가 말한 ‘튜너 문서’는 실제 파일을 확인해 Tune-up 문서인지 안테나 tuner 문서인지 구분한다. 두 문서를 같은 것으로 합치지 않는다. Power Target은 제조사 설정 목표이고 계측 출력과 규정 한계값은 별도 필드다.

각 사실은 값·단위·출처 위치·추출 방식·확인 상태를 가진다. AI 추출 신뢰도는 기술 확인의 대체물이 아니다. 상충하는 두 값을 발견하면 임의로 최신 파일 하나를 채택하지 않고 충돌과 영향을 표시한다. 사용자의 보완 답변도 누가·언제·어떤 사실을 확인했는지 남긴다.

## 5. 규정·방법과 시험 커버리지

시험일의 규정과 허용 시험방법 판본을 고정한다. 2026-10-23 웹 열람에서 eCFR §15.31(a)(3), §15.37(s)는 ANSI C63.10-2020을 명시했다. 이는 표준 원본 전체 또는 최신 KDB 첨부를 확보했다는 뜻이 아니다. KDB 558074, 복수 송신 출력/안테나 구성에 대한 662911 및 해당 관련 자료의 현행 첨부는 수집 담당이 대조한다.

아래는 구현할 커버리지의 출발점이다. 실제 방법의 검파기·RBW/VBW·스윕·샘플링·듀티 보정·설정값은 확인한 원문과 조항으로 채운다. 표의 존재만으로 운영 가능한 방법이 등록되지는 않는다.

|---|---|---|
| W24-BW | 6 dB 대역폭 | §15.247(a)(2). b의 DSSS와 g/n의 OFDM 등 실제 제품 방식을 확인한다. b라는 이름을 FHSS 시험으로 잘못 매핑하지 않는다. |
| W24-PWR | 최대 전도 출력 | §15.247(b)(3), (b)(4). 선택한 측정 방식, 전체 송신 체인과 안테나 이득 조건을 연결한다. |
| W24-PSD | 전력 스펙트럼 밀도 | §15.247(e). 출력 측정과 일관되는 방법을 사용한다. |
| W24-OOB | 대역 경계·대역외 전도/해당 허용 방법의 방출 | §15.247(d). 전력 측정 방식에 따른 감쇠 조건을 연결한다. |

| W24-AC | AC 전원단 전도 방출 | §15.207. 배터리 탑재만으로 제외하지 않고 충전 중 동작·어댑터·간접 AC 연결을 판단한다. |
| W24-ANT | 안테나 구성·연결·이득 검토 | §§15.203/15.204 및 §15.247의 출력/이득 조건. 제품별 증거가 필요하다. |
| W24-SETUP | 공통 측정 조건·구성·사이트·전원·범위 검토 | §§15.31/15.33/15.35, 확인한 C63.10 조항과 교정/사이트 증거. |
| W24-TARGET | 제조사 출력 목표와 실제 설정/출력 검증 | 제조사 문서·허용 범위에 대한 제품 검증이다. 독립된 FCC 한계값으로 오인하지 않는다. |
| W24-EXPOSURE | RF exposure 연관 근거 인수 | §15.247(i). 별도 평가 결과/면제 근거의 해당 여부를 검토한다. SAR 자동 측정 개발을 이 버전에 추가하지 않는다. |

99% 점유대역폭 등 추가 항목은 해당 방법/신청 요구의 근거가 있을 때 등록한다. 확인되지 않은 항목을 모든 b/g/n 제품의 필수 FCC 시험이라고 만들지 않는다.

시험 조합은 제품이 지원하는 모드·채널·대역폭·레이트/MCS·체인·출력 조건에서 만든다. n의 HT20/HT40, 다중 체인은 실제 지원 여부를 확인한다. 1/6/11 채널이나 단일 레이트를 모든 구성의 기본 최악 조건으로 고정하지 않는다. 사전 탐색 결과와 방법의 축소 근거를 보존하고 최종 시험 조건을 선택한다.

요구사항은 `applicable / not_applicable / undetermined`를 가지며, 실행은 `pending / completed / invalid / aborted / blocked` 등으로 별도 관리한다. 계측 능력이 없는 항목은 `not_applicable`이 아니라 `blocked`다. 각 항목에 이번 RF 실행 범위인지 외부 연관 근거인지를 명시한다. `scope_complete`는 W24-EXPOSURE를 제외한 검증된 RF 요구 목록 전체에서 적용성 미확정 항목이 없고, 모든 적용 항목의 유효 결과 또는 검토 근거와 모든 비적용 항목의 정당한 근거가 있을 때 참이다. 유효한 부적합 결과도 시험 완료일 수 있으며 완료와 적합 판정을 분리한다.

W24-EXPOSURE는 `linked_evidence_status`로 별도 관리한다. 이 근거가 미확보여도 RF 측정·범위 완료·검토된 RF 초안은 생성할 수 있다. 해당 초안에는 연관 근거의 미확보 상태와 보고 범위 제한을 표시한다. 필요한 연관 근거가 해결되지 않으면 전체 §15.247 적합을 주장하거나 이 파이프라인의 최종 발행 준비가 끝났다고 표시하지 않는다. RF exposure 완료만으로 스마트폰 전체 FCC 인증 준비가 완료되는 것도 아니다.

## 6. 장비 선정과 사용자의 연결 응답

장비 대장은 후보 검색에 사용한다. 시험이 요구하는 주파수 범위·검파/대역폭·동적 범위·트리거·옵션·교정·사이트 조건과 실제 자산을 대조해 연결 요청을 만든다. ‘N90’은 예시 표현이며 정확한 모델·옵션·펌웨어가 확인되기 전에는 특정 Keysight 모델 등으로 자동 확정하지 않는다.

연결 요청은 `action_id`, `case_id`, `plan_revision`, `setup_revision`, 사용 장비/시료 ID, 포트 간 연결도, 케이블·감쇠기·보정값의 근거, 허용 입력 조건, 필요한 사용자 확인·사진, 만료 조건을 포함한다. 사용자에게는 ‘무엇을 어디에 연결하는지’와 ‘어떻게 완료를 확인할지’를 보여준다.

사용자의 ‘연결했습니다’는 해당 요청에 대한 응답이다. 장비 식별 응답, 올바른 시료, 제어 연결, 경로 증거, 계측기 보호 설정을 검사한 후 RF 사전 검증으로 진행한다. LAN 연결 성공으로 RF 케이블·포트 연결까지 증명했다고 처리하지 않는다. 자동 확인할 수 없는 물리 경로는 사용자 확인/사진 등 명시된 근거와 그 한계를 남긴다.

초기 USB 연결에서는 제품 식별·펌웨어·도구 실행·설정/조회 능력 등 비송신 사전검사를 할 수 있다. RF 경로와 계측기가 준비되기 전에는 ‘RF 시험모드 검증 완료’로 표시하지 않는다. 실제 송신 확인은 보호된 RF 구성과 검증된 시작 조건을 충족한 뒤 수행한다.

연결 안내는 시험 유형별로 다르다. 전도 RF에는 경로 손실·감쇠기·분석기/전력계, 방사에는 사이트·안테나·케이블·위치/편파·수신기, AC에는 전원/충전 구성·LISN·수신기 등의 능력과 증거를 연결한다. 다른 연결로 바뀌면 기존 setup 검증은 자동 재사용하지 않는다.

## 7. DUT·계측기 실행과 MCP

현장 실행기는 장비/시료 세션과 잠금을 소유한다. AI는 `prepare_test`, `verify_setup`, `run_test`, `stop_test`, `get_status` 같은 의미가 정해진 동작을 요청한다. 이 이름은 제안이며 현재 제공되는 MCP 도구가 아니다. 기존 `lab_record_run`을 실제 장비 실행이라고 포장하지 않는다.

DUT 어댑터는 식별, 지원 기능 조회, 시험모드 준비, 조건 설정/읽기, 송신 시작/정지, 상태/로그 수집을 구현한다. 제조사 API/SDK·CLI·공식 스크립트를 우선 활용하고 필요한 경우 GUI 조작도 같은 계약으로 감싼다. SDK 호출 성공이나 GUI 문구만으로 실제 RF 상태를 확정하지 않는다. 새 어댑터는 문서 해석·생성·검사를 AI가 보조할 수 있으나, 실제 검증 없이 운영 목록에 들어가지 않는다.

어댑터의 호환 범위는 제조사/제품 모델·HW/FW·도구 버전·지원 모드와 조합으로 기록한다. 미지원 레이트·채널·체인은 누락 없이 반환한다. 지원 여부를 확인할 수 없으면 `unknown`으로 보류한다.

실행은 `전제·잠금 확인 → 계측기 보호/설정 → DUT 설정 → 상태 조회 → 제한된 RF 확인 → 본 측정 → 완료/데이터 유효성 확인 → 원본 확정 → 다음 단계/정지`를 따른다. 요청값, 읽힌 값, 실제 관측값을 구별한다. DUT가 응답해도 송신이 없거나 다른 채널·출력 감소가 관측되면 유효 시험으로 완료하지 않는다.

시간 초과·연결 단절·AI 작업자의 실행 권한 임대 만료 때는 현장 정책에 따라 정지/복구한다. 사용자 대화창을 닫았다는 이유로 작업 소유권이 사라지지는 않는다. 재시도는 상태를 확인하고 새 attempt로 남기며, 이전 RF ON이나 측정 완료를 추정해 반복하지 않는다. 중단 뒤 재개할 때는 시험 시료·펌웨어·setup·보정·장비 상태를 다시 확인한다. 장비/절차별 정지 동작은 실제 매뉴얼로 검증하며, 모든 장비에서 특정 명령 하나가 동작한다고 가정하지 않는다.

첫 현장 실증은 해당 시험 PC에서 실행되는 MCP/현장 서비스를 기본으로 제안한다. 도구에 필요한 OS는 실제 제조사 패키지를 기준으로 선정한다. 클라우드는 코드 개발·문서/계획 작업을 수행한다. 클라우드 AI가 현장 장비를 직접 운전하려면 별도로 검증한 인증 연결/중계가 필요하며 현재 클라우드가 USB/LAN 장비에 접근할 수 있다고 가정하지 않는다. 원격 연결 부재는 현장 통합 검증의 준비 항목으로 표시한다.

## 8. 원시 데이터·계산·변경 영향

원본 트레이스·계측기 원본 파일·응답·DUT 로그·사진을 보존하고, 정규화한 관측 데이터를 별도로 생성한다. 스크린샷 한 장만으로 모든 원시 데이터가 확보되었다고 보지 않는다.

관측/실행에는 다음을 연결한다:

- case/sample/configuration/plan/run/attempt ID, 방법·규정·도구·어댑터 버전, 시간과 단위.
- 주파수 축·레벨 축·배열 또는 원본 파일, 계측 설정/RBW/VBW/검파기/스윕/트리거/평균·듀티 조건과 완료 증거.
- DUT 모드·채널·대역폭·레이트/MCS·체인·목표/조회/관측 출력, 배터리/온도 등 방법상 필요한 상태.
- 장비 ID/교정, 실제 RF 기준면·경로 손실/불확도, 계측기 내부 보정 여부, setup 증거.
- 유효/중단/실패·재시험 이유, 원본 해시와 각 파생 데이터의 원본 참조.

계산은 버전 관리한 함수로 수행하고, DUT 커넥터 기준면과 계측기 입력 기준면을 구별한다. 보정의 중복 적용, 다중 체인 dBm 값의 산술 덧셈, 필요한 피크/평균/듀티 조건의 혼용을 검사한다. Power Target 충족 여부와 FCC 한계값 충족 여부를 각각 계산한다. 측정불확도와 판정 규칙은 해당 방법/기관 정책에 연결하며 임의의 공통 여유값을 만들지 않는다.

제품 정보·출력 목표·안테나·펌웨어·setup·교정·방법이 바뀌면 영향받는 계획·측정·계산·보고서를 식별한다. 원본은 유지하고 새 revision/attempt를 만든다. 이전 결과를 자동 재사용하려면 명시된 재사용 조건과 증거가 필요하다. 파일 갱신을 이유로 진행 중인 시험의 기준을 조용히 바꾸지 않는다.

## 9. 성적서와 AI 리뷰

성적서는 공통 데이터에서 HTML/PDF와 구조화 데이터로 생성한다. 제품/시료 식별, 시험 범위·규격/방법 판본, 환경·사이트·장비/교정, 동작 구성, 선정 근거, 절차, 수치·한계값·마진·불확도/판정 규칙, 그래프·사진, 비적용/보류/일탈, 검토 이력을 포함한다. 필요한 세부 필드와 배치는 확보한 방법/보고 요구에 맞춘다.

숫자·표·그래프는 원본과 계산 결과에서 생성한다. AI가 수치를 작성하거나 표의 결과를 직접 고쳐 합격시키지 않는다. 정정은 원인 데이터/계산을 수정한 새 버전을 재생성하는 방식으로 한다.

리뷰는 두 종류의 결과를 함께 보여준다:

1. 결정적 검사: 항목/조건 누락, 단위·계산·한계값·반올림 불일치, setup/시료/판본 불일치, 오래된 결과 재사용, 미완료/합성 자료 혼입.
2. AI 기술·문서 검토: 원문·제품·계획·원시 파일·보고서를 함께 읽고 최악 조건 근거, 설명과 결과의 모순, 빠진 증거, 이해하기 어려운 표현을 지적한다. 각 지적에 근거 위치·심각도·후속 조치를 둔다.

작성과 리뷰의 실행 기록을 분리하되 AI 둘의 동의 자체를 기술 검증으로 취급하지 않는다. 문구/레이아웃 수정은 재생성하고, 실제 조건/원본의 문제는 재측정 또는 근거 보완 작업으로 돌린다. 유효한 부적합 결과는 그대로 보고하며 합격할 때까지 재시험하는 정책을 두지 않는다.

`AI reviewed`, `scope_complete`, `linked_evidence_status`, `technically validated`, `authorized for issue`는 별도 상태다. 최종 발행 준비에는 RF 범위 완료, 필요한 연관 근거의 해결, 미해결 중대 지적 없음, 기술 검증 및 기관의 발행 권한/절차 충족이 필요하다. 현재 코어의 CLI 검토 플래그를 AI 리뷰 결과 하나로 자동 승인하도록 변경하지 않는다. 검증된 기준 방법과 어댑터가 등록된 뒤 정상 반복 시험은 매 단계 사람의 승인을 요구하지 않고 자동 처리한다. 기관 발행 권한이 구성되지 않은 초기 출력은 검토 완료 초안으로 표시하며, 인증기관의 결정·서명·포털 제출을 완료했다고 표시하지 않는다.

## 10. 현재 코어와 새 구현 범위

[현재 파이프라인](../../fcc/pipeline_usage.md)은 자료 ZIP 인수·시험건/방법/계획·오프라인 실행 기록·두 가지 공통 계산·초안 보고·stdio MCP를 제공한다. 폴더 해석, 자동 누락/적용성 판단, DUT/계측기 운전, 방법별 전체 측정, 자동 커버리지 판정, 위의 리뷰 과정은 새 구현 대상이다.

현재 SQLite와 해시 기반 원본 저장을 확장하고 필요할 때 스키마 마이그레이션을 추가한다. 주요 추가 객체는 영속 작업/이벤트, 문서별 제품 사실, 누락/충돌, 시험 커버리지, 제품 구성, 장비/도구 능력, 연결 요청/확인, setup revision, 실행 단계/관측, 검토 지적과 변경 영향이다. 테이블 이름·내부 API·폴더 감시 라이브러리는 구현자가 정할 수 있다. 기관별 다중 사용자 웹 서비스나 특정 실행 프레임워크 도입은 이번 시작 조건이 아니다.

## 11. 개발 순서와 완료 기준

| 단계 | 제공하는 기능 | 확인할 완료 증거 |
|---|---|---|
| A. 접수·검토·계획 | 폴더 감시·영속 작업·AI 호출/응답 재개 → 출처 있는 제품 사실 → 누락/충돌 → b/g/n 시험 및 준비 목록 | 대화창 종료·서비스 재시작 후 복구, 누락 안테나 이득·출력 목표, 서로 다른 FW/모델, 충전 조건과 모드 차이에 대한 기대 결과 |
| B. 제어·연결과 전도 출력 한 흐름 | 사용자 연결 요청 → DUT 사전검사/RF 검증 → 전도 출력 → 원시 기록 → 계산 → 초안 → 리뷰 | 가상/기록 재생 후 실제 도구·계측기 한 조합에서 기준 측정과 비교. 이 단계만으로 §15.247 전체 완료를 선언하지 않음 |
| C. 범위 내 시험 확장 | BW·PSD·대역 경계/불요파·방사·해당 AC 시험과 연결 변경 | 각 방법의 원문·계산·장비/셋업·기준 비교, 누락 감지와 무효 시험 처리 |
| D. 전체 시범 운영 | 실제 스마트폰 의뢰자료부터 범위 내 성적서와 리뷰까지 반복 | 아래 수용 기준과 단계별 사람 개입/중단/복구 기록 |

제어도구가 없을 때에는 API형·CLI형·제한 기능형 가상 DUT/계측기로 같은 실행 계약을 검증한다. 연결 끊김·응답 지연·설정 무시·다른 펌웨어·미지원 구성·출력 감소를 재현한다. 가상 시험은 명시적으로 합성 표시를 유지하며, 스펙트럼 물리·측정 정확도·현장 반복성 검증을 대신하지 않는다.

수용 기준:

1. 신청서와 제품 파일을 넣으면 시험 목록·근거·누락·필요 장비가 생성되고, 임의 숫자로 빈칸을 채우지 않는다.
2. 안테나 이득/출력 목표 누락 또는 문서 충돌이 영향을 받는 시험·판정으로 연결된다. 원문 판본/방법이 없으면 해당 방법은 실행 가능으로 표시되지 않는다.
3. 실제 지원 b/g/n·대역폭·체인에 맞는 계획을 생성하며 미지원/미확정 조건과 정당한 비적용을 구별한다.
4. ‘연결 완료’ 응답이 다른 시험건·오래된 setup에 적용되지 않는다. 장비 ID나 경로 증거가 다르면 실행하지 않는다.
5. 도구가 성공을 반환해도 실제 RF 상태가 요구와 다르면 시험모드 검증/측정 완료가 되지 않는다.
6. 전도 RF 시험만 끝났거나 충전 중 동작 장치의 필요한 AC 시험이 비어 있으면 범위 완료를 표시하지 않는다. RF 범위 완료·인체노출 근거 미확보의 조합은 허용하되, 제한 표시가 없는 전체 적합 선언이나 최종 발행 준비 완료는 허용하지 않는다.
7. 한 보고서 수치에서 조건·방법·보정·계산·원시 파일까지 추적하고 다시 계산할 수 있다. 합성 데이터는 실측 결과로 사용할 수 없다.
8. 리뷰는 의도적으로 넣은 단위 오류·조건 누락·문서 모순·이전 결과 혼입을 탐지하며 근거와 수정 작업을 반환한다.
9. 통신 단절·중단·재시작과 제품/펌웨어/setup 변경 뒤에 필요한 재확인·재측정을 수행하고 실패 원본을 보존한다.
10. 실제 기준 측정과의 허용 차이는 방법·장비·불확도에 근거해 **검증 전에** 정한다. 가상 데이터나 과거 단위 테스트 통과 수를 실측 검증으로 보고하지 않는다.
11. 폴더 이벤트·연결 완료 응답이 영속화되고, 대화창 종료·AI 오류·서비스 재시작 후 같은 상태에서 필요한 확인을 거쳐 이어진다. 중복 이벤트가 중복 RF 동작을 일으키지 않는다.

정확한 스마트폰·펌웨어·도구, 분석기/전력계와 옵션, RF 포트/경로, 방사/AC 자원, 기관 발행 조건은 현장 통합 전 채울 입력이다. 이를 기다리며 A와 가상 B의 개발을 멈출 필요는 없다. 실제 정보를 받기 전에는 해당 연결의 지원/성능을 미확인으로 유지한다.

## 12. 자료 준비 담당과 출처

수집 담당의 첫 배치는 [Wi-Fi 2.4 GHz b/g/n 우선 자료](../../../handoff/WIFI24_BGN_FIRST_BATCH.md)를 따른다. 전체 304건·장비 2,867모델은 후속 수집 대장으로 유지하며, 전부 모일 때까지 이번 구현을 기다리지 않는다.

설계 시 확인한 자료와 한계:

- [eCFR §15.247](https://www.ecfr.gov/current/title-47/section-15.247): 2026-10-23 본문 웹 열람. 출력·대역폭·PSD·대역외·인체노출 연결의 범위 확인. 원문 패키지/방법 승인과는 별도다.
- [eCFR §15.31](https://www.ecfr.gov/current/title-47/chapter-I/subchapter-A/part-15/subpart-A/section-15.31), [§15.37](https://www.ecfr.gov/current/title-47/chapter-I/subchapter-A/part-15/subpart-A/section-15.37), [§15.38](https://www.ecfr.gov/current/title-47/chapter-I/subchapter-A/part-15/subpart-A/section-15.38): 같은 날 웹 열람. C63.10-2020 및 2025-10-30 전환 조항 확인. C63.10 원본·정오표의 적용 검토는 미완료다.
- [eCFR §15.207](https://www.ecfr.gov/current/title-47/chapter-I/subchapter-A/part-15/subpart-C/section-15.207): 같은 날 웹 열람. 충전/간접 AC 연결의 적용 조건 확인.
- [FCC KDB 558074](https://apps.fcc.gov/oetcf/kdb/forms/FTSSearchResultPage.cfm?id=21124&switch=P), [KDB 662911](https://apps.fcc.gov/oetcf/kdb/forms/FTSSearchResultPage.cfm?id=49466&switch=P): 공식 페이지의 검색 결과에서 후보 첨부 식별. 상세 페이지 재열람 실패, 최신 첨부 원본은 미확보다. 검색 색인의 판본을 최신 확정본으로 고정하지 않는다.

사용자 흐름·범위는 이 대화에서 확정되었다. 실행 구조·내부 객체·개발 단계는 이 문서의 설계 제안이며 설계 검토 뒤 구현 계획으로 구체화한다.
