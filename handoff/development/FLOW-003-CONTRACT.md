# FLOW-003-CONTRACT — 접수에서 가상 실행 결과까지 후속 연결 검토

2026-10-24, Asia/Seoul. VLAB-HARNESS-002의 통합 뒤 개발 후속 배정이 비어 있었음을 확인했다. 총괄이 다음 연결 계약을 준비하며 개발1~4와 P01에 아래 검토를 실제 배정한다. 이 문서는 계약 검토 착수이며 기능 구현 완료나 새 API 확정이 아니다.

기능 기준은 `35dc0f59e2d9368e79e76fa552c35271e695509f`다. [전체 사용자 흐름](../../docs/fcc/wifi24_delivery_roadmap.md), [최종 하네스 인수](INTEGRATION-003.md)와 현재 코드를 근거로 접수→시험 준비/계획→가상 실행→근거·결과 조회 사이의 최소 연결을 제안한다. 모든 접수를 스마트폰/FCC로 간주하지 않으며 실장비·실제 모델·재시작 재개를 실행했다고 표시하지 않는다.

| 담당 | 이번 검토 산출물 |
|---|---|
| 개발1 | PDF 페이지 추출을 기존 접수 분석에 연결할 때 재사용할 함수·revision/출처 계약·누락/충돌 보존과 최소 회귀 사례 |

| 개발3 | 현재 전도 예제/센서 목표를 명시적 가상 방법으로 선택하는 adapter 경계·지원/미지원 조건·fresh 취득 검증 |

개발 담당은 기존 clone/브랜치/완료 커밋과 실패 기록을 보존한다. 이번 단계는 기준 코드 읽기와 자기 `.local/`의 계약 메모만 작성하며 공통 DB/기존 구현/다른 clone/공유 수집 파일을 수정하지 않는다. 제안은 근거 파일·함수, 최소 입출력 예, 최대 3개 미해결 계약, 수용 검사, 후속 구현 소유 파일을 포함해 총괄 한 창구로 한 번 보고한다. 이번 검토가 끝난 것을 제품 기능 완료로 집계하지 않는다.

수집1~8의 실행과 배정은 계속 P01이 담당한다. 현재 요청 묶음 완료를 전체 수집 완료로 확대하지 않고, 근거가 있는 추가 공백에 대해서만 P01이 재배정한다. 사용자 추가 raw/Licensed 암호·원본 재첨부를 새 선행조건으로 만들지 않는다.
