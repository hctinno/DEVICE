# 게시 세션 — 로컬 인수·패키징·Git 단독 담당

상태: DRAFT. 분업 실행 전 사용자 검토와 실제 경로/배정이 필요하다. **수집 세션은 Git을 사용하지 않고 P01만 로컬 Git을 조작한다는 경계는 이미 사용자 결정이다.**

## 착수 준비

1. 기존 프로젝트·브랜치·미커밋 변경·수집 폴더·완성/진행 중 요청을 읽어 목록화한다. 옮기거나 초기화하지 않는다.
2. 기존 수집자에게 Git 작업을 하지 않는 새 역할이 적용됐는지 확인한다. 확인 전 단일 Git 작성자 전환이 완료됐다고 보고하지 않는다.
3. 승인된 지시 전체 SHA를 고정하고 `.local/collection/briefs/<sha>/`에 공통 지시·역할 파일·schema·필요 요청 목록을 복사한다. 사본 해시와 `activation=approved`를 기록한다. 현재 DRAFT는 실행 지시로 활성화하지 않는다.
4. `.local/collection/control/<version>/`에 요청/모델별 단일 담당·우선순위·범위 판정·legacy 예약·원본 담당을 둔다. 기술적 경계는 클라우드 담당에 확인하되 확인된 작은 작업열은 먼저 배정한다.
5. S01~S08별 실제 경로와 지시 SHA·배정 버전을 채운 시작 문장을 사용자에게 제공한다. 새 세션을 사용자 동의 없이 만들지 않는다.

## 수집자와 인계하는 방식

수집자는 자기 `work/<batch_id>`에서 작성하고, 모든 파일을 닫은 뒤 `inventory.json`과 `READY.json`을 만든다. inventory는 payload/metadata의 경로·크기·해시, READY는 inventory 해시·배치/세션 ID·지시 SHA·배정 버전을 담는다. 두 제어 파일 자신은 inventory 파일 목록에서 제외한다. 동일 파일시스템에서 `ready/<batch_id>`로 rename하며 이후 수정하지 않는다. 기존 완성 폴더는 이동을 강제하지 않고 동결 선언·동일한 목록 검증 후 snapshot으로 인수할 수 있다.

P01은 ready를 자기 `.local/collection/p01/snapshots/`에 복사한다. 전체 파일 목록·해시·크기·경로·일반 파일 여부를 검사하고, 심볼릭 링크·비정상 경로·불일치는 반려한다. ready 원본은 수정하지 않는다. 인수/반려/게시 상태는 P01의 별도 receipts에 기록하며 반려 사유에는 정확한 파일과 필요한 정정을 남긴다. 정정은 새 batch ID로 받는다.

## 패키징과 게시

- [기존 schema](../collection_manifest.schema.json)와 [게시 규칙](../../materials/README.md)을 사용한다. 로컬 READY/배정/receipt 속성을 manifest에 추가하지 않는다.
- 공개 재배포가 확인된 원본만 공개 저장소에 넣는다. 권리 미확인·내부/유료 원본은 제외하고 공개 가능한 출처/조건만 기록한다. 로컬 파일의 존재를 클라우드 전달 완료로 표시하지 않는다.
- 로컬 생성 색인·참조 관계·현황은 공개 가능한 범위에서 `materials/collection/<run_id>/`의 일반 파일로 먼저 게시한다. metadata를 downloaded record로 넣으려고 가짜 HTTP URL을 만들지 않는다.
- 이미 제출한 package/document ID는 불변이다. 같은 document ID의 request_ids·시각·경로도 바꾸지 않는다. 연결 추가와 정정은 새 참조/개정 기록으로 처리한다.
- ZIP 내부 manifest와 바깥 JSON은 같은 바이트로 저장한다. 모든 ZIP 일반 파일은 manifest에 등록한다. 압축 후 50 MiB 이하를 권장하며 현재 importer의 해제 총량 512 MiB/10,000 entries 한계를 지킨다. 큰 원본의 저장 방식은 별도 정하고 임의 분할하지 않는다.
- P01 전용 임시 DB에서 이미 게시한 배치와 후보를 누적 인수한다. 공용 운영 DB를 사용하지 않는다. 새 패키지 단독 검사만으로 전체 ID 충돌이 없다고 보고하지 않는다.
- 현재 로컬 브랜치와 하나의 게시 원격 브랜치를 사용한다. 기존 작업 트리/수집 경로를 보존하고 수집 중 checkout/reset/clean을 하지 않는다. 충돌 시 게시를 보류하고 클라우드 담당과 조정한다.
- 완성된 `materials/packages/`, `materials/manifests/`, `materials/collection/<run_id>/` 경로만 명시해 staging한다. 전체 폴더의 변경을 일괄 add하지 않는다. `.local/`, 사용자 수정, 자격증명은 포함하지 않는다.
- push 성공과 원격 SHA를 확인한 뒤 receipt와 보고에 게시 결과를 남긴다. 로컬 완료·커밋 완료·원격 게시·클라우드 기술 인수를 구별한다.

공통 `materials/STATUS.md`와 로컬 배정/출처 색인은 P01 단독 작성이다. 클라우드 담당은 `docs/material-intake/`에서 별도 기술 인수 기록을 남긴다. 기존 코어·schema·SQLite·규칙·어댑터를 P01이 수정하지 않는다.

자동 폴더 감시·스냅샷 검사·중복 연결 집계는 아직 구현되지 않았다. 이 문서는 역할과 파일 인계 계약이며 서비스가 실행 중이라는 뜻이 아니다.
