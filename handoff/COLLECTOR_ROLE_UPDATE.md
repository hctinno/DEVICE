# 진행 중인 수집의 역할·우선순위 갱신

2026-10-23 (Asia/Seoul). 대상은 처음 받은 배치를 로컬에서 계속 수집 중인 에이전트다. **기존 결과와 진행 상태를 보존하면서 최신 우선순위를 적용한다.** 프로젝트 개발을 인계하는 문서가 아니다.

## 1. 무엇이 달라졌는가

최신 사용자 결정은 **FCC RF·EMC·SAR를 1차 구축 목표**로 삼고, 수집과 Git 게시를 분리하는 것이다. 수집자는 Git을 사용하지 않고 하나의 로컬 프로젝트 안에서 자료만 준비하며 P01이 게시한다. **스마트폰 2.4 GHz Wi-Fi b/g/n / FCC §15.247**은 그 안의 첫 전체 흐름 실증이다. 관련 원본을 먼저 반환하되 SAR 등 다른 담당의 수집을 이 완료까지 미루지 않는다. [8개 역할](parallel/README.md)은 검토안이며 아직 새 세션에 배정된 것은 아니다.

전체 304개 규정 등 요청, 2,867개 모델과 식별 미완료 항목은 이번/지원/후속/식별 필요로 구분해 보존한다. 이 전체를 끝내거나 새 색인을 완성해야 이미 확보한 첫 원본 배치를 반환할 수 있는 것은 아니다. 같은 원본은 해시/판본으로 재사용하고 중복 다운로드를 요구하지 않는다.

## 2. 역할 경계

| 영역 | 수집 담당이 준비하는 것 | 파이프라인 담당이 만드는 것 |
|---|---|---|
| 규격·적용성 | 현행/전환/대체 판본과 공식 원문, 관련 조항·적용 조건의 출처 색인 | 제품별 적용 판단, 필수 입력/시험 목록, 실행 가능한 규칙과 방법 프로필 검토·등록 |
| 제품 접수 | 공개 신청/제품 자료 사례, 요구되는 사실·단위·조건·근거 위치 | 문서 해석/OCR, 사실 DB, 누락·충돌 확인, 질문과 시험계획 생성 |
| DUT/계측기 | 공식 매뉴얼·API/SCPI/SDK·예제, 모델/옵션/버전 범위, 시작/완료/오류/정지/원본 내보내기 근거 | 제어 어댑터, 연결 검증, 세션·잠금, 실제 RF 동작 확인과 복구 |
| 시험·계산 | 방법의 설정·보정·판정·필수 기록 요소가 있는 페이지/표/수식, 변경 관계 | 단계별 시험 실행, 보정·불확도·판정 계산, 최악 조건 선정, 방법별 검증 |
| 성적서·리뷰 | 같은 FCC ID/제품에 연결된 공개 성적서·셋업 사진과 필수 보고 요구 | 새 원시 데이터/성적서 형식, 표·그래프·PDF, 자동 검사와 AI 리뷰 |
| AI 하네스 | 필요한 규정·제품/장비 도구의 근거 자료를 제공 | 모델/MCP 연결, 영속 작업, 상태·자동 진행·예외 요청·중단/재개 구현 |
| 품질·운영 | 공식 품질/교정/보고 요구와 공개 성능검증 절차, 비공개 자료의 누락 목록 | 기준 측정 대조, 현장 검증, 변경 영향, 운영·발행 정책 연결 |

수집 단계의 사실 추출·요약은 **원문 위치가 있는 검토용 후보 자료**다. 수집자가 승인된 운영 규칙·시험방법·장비 지원 상태를 확정하지 않는다. 파이프라인 담당은 출처를 대조해 구현·검증하며 수집자의 요약을 곧바로 실행 규칙으로 활성화하지 않는다.

## 3. 우선 반환할 세 묶음

### A. 규정·방법 원본

[WIFI24_BGN_FIRST_BATCH.md](WIFI24_BGN_FIRST_BATCH.md)의 조문·KDB·허용 표준 판본과 관련 첨부부터 준비한다. 일부 원문이 접근 제한이면 그 판본·URL·제약·다음 조치도 함께 반환하고 나머지를 묶어 두지 않는다. 표준의 최신 발행판과 FCC가 허용하는 판본을 별도로 기록한다.

### B. 실제 제어에 필요한 문서

2.4 GHz 전도 출력의 첫 실증에 사용할 분석기/전력계·RF 경로 문서와 제조사 DUT 도구의 공개 인터페이스를 우선한다. 정확한 모델이 미정이면 대장의 관련 후보와 확인한 지원 범위를 반환하고 현장 선정은 파이프라인 담당과 사용자가 한다. ‘N90’ 같은 약칭을 특정 모델로 확정하지 않는다. 이후 방사/AC 자원 문서를 이어서 반환한다.

조작 매뉴얼 외에 모델 식별, 설정/조회, 측정 완료 확인, 오류 응답, 제한 시간·정지/복구, 트레이스/원본 전송, 옵션·펌웨어 호환과 입력 한계가 설명된 위치를 찾는다. 실제 장비 명령·설치파일·예제 스크립트는 실행하지 않는다. 공개 문서만으로 제조사 사설 제어도구가 준비됐다고 표시하지 않는다.

### C. 개발용 출처 색인과 공개 사례

이미 원본에서 확인한 부분부터 다음 색인을 CSV/JSON/Markdown 등의 metadata 파일로 반환한다. 확인되지 않은 값을 채우기 위해 추가 추론을 하지 않는다.

- 제품 입력 색인: 필요한 사실, 단위, 적용 조건, 문서 ID와 조항/페이지. 예: 안테나 이득·출력 목표·체인·대역폭·충전 조건.
- 시험방법 색인: 시험항목, 방법/설정 선택 조건, 기록할 원시 값·보정·보고 요소, 문서 ID와 조항/페이지/표.
- 제어 인터페이스 색인: 모델/도구와 적용 버전, 제어 기능, 공식 명령/API 설명 위치, 미지원/미확인 범위.
- 공개 사례 색인: FCC ID·모델·문서 판본, RF 성적서·셋업 사진·운영 설명의 연결. 보고서 그래프와 실제 원시 트레이스를 구별한다.

각 항목의 근거 원본은 `document_id`로 연결한다. 수집 사실·원문 인용/추출·수집자 해석·미확인을 구별한다. 표·수식·단위가 추출 과정에서 빠졌다면 그 위치를 남긴다. 공식 요구와 사례에서만 보이는 관행을 섞지 않는다.

색인은 우선 자기 로컬 metadata 파일로 반환한다. P01은 공개 가능한 색인을 `materials/collection/<run_id>/`의 일반 파일로 게시할 수 있다. 기존 importer는 downloaded metadata에도 HTTP(S) 출처/다운로드 URL을 요구하므로, 로컬 생성 파일을 원천 문서처럼 꾸미거나 가짜 URL을 만들지 않는다. 패키지에 넣을 경우 실제 접근 가능한 출처와 기존 schema를 따른다. 새 속성을 manifest 최상위에 추가하거나 DB를 수정하지 않는다. 원본을 먼저 반환하고 색인은 후속으로 보완할 수 있으며 공유한 원본 레코드/배치는 고쳐 덮어쓰지 않는다.

## 4. 로컬 작업 보존과 게시 담당으로의 인계

진행 중인 다운로드·원본·목록·작업 트리를 보존한다. **수집자는 fetch/show/브랜치 전환/commit/push를 포함한 Git 작업을 하지 않는다.** P01이 최신 고정 지시를 로컬 사본으로 제공한다. 원래 시작 SHA가 기록되어 있으면 보존하고, 새 사본의 적용 SHA와 배정 버전을 별도로 기록한다. 값이 없으면 추정하지 않는다.

현재 폴더를 새 경로에 맞추려고 이동·삭제·초기화하지 않는다. 기존 확보/진행 중 request_id를 P01에게 알려 예약하고 다른 수집자에게 중복 배정하지 않게 한다. 기존 수집자가 Git 금지 지시를 확인하기 전에는 P01 단독 Git 운영으로 전환됐다고 가정하지 않는다.

파일 쓰기가 끝난 묶음부터 동결 선언과 파일 목록·크기·해시를 P01에 넘긴다. 신규 폴더 구조의 work/ready 계약은 [P01 지시](parallel/P01.md)를 따른다. P01이 snapshot을 검수·패키징하고 [게시 절차](../materials/README.md)에 따라 커밋·푸시한다. 수집자는 자기 상태 기록에 다음을 포함한다.

- 원본 확보 / 열람만 가능 / 미확보 / 미착수의 구분과 요청 ID. 미착수는 진행 현황 metadata에 기록하고 manifest에 정의되지 않은 상태를 새로 넣지 않는다.
- 배치 ID, 원본/파생/metadata 수, 출처·판본·권리·해시, 인수 검사 결과.
- 부족한 파일·조항·기능, 접근 제한, 필요 담당과 다음 조치.
- 원래 시작 기준 SHA(알 수 있으면), 적용한 지시 SHA, 배정 버전, 로컬 동결 배치 ID와 P01 receipt. 결과 커밋은 P01이 보고한다.

로컬에 있는 파일은 다른 계정/클라우드에서 자동 접근할 수 없다. 공개 재배포가 허용되는 자료만 현재 공개 저장소에 공유한다. 내부 라이선스·비공개 제조사 패키지·고객 자료는 권한 있는 비공개 보관 경로와 접근 가능 여부를 별도로 관리한다. 로컬 절대 경로나 접근 불가 링크를 남긴 것만으로 인계 완료로 표시하지 않는다. 사용자에게 ZIP을 직접 내려받아 재첨부하도록 요구하지 않는다.

## 5. 파이프라인 담당과 현장의 후속 작업

파이프라인 담당은 공유된 브랜치/커밋을 검토·인수하고, 중복·해시·판본·적용 범위·권리와 출처 내용을 확인한다. 코드·데이터 계약·방법 구현·성적서 형식·AI 하네스는 파이프라인 담당이 변경한다. 필요한 추가 조사만 request_id/문서/조항/사용 목적/우선순위로 구체화해 요청한다. 자료 전체 반환을 기다리지 않고 접수·상태·가상 제어 계약 등 독립 개발을 진행한다.

실제 스마트폰/시험용 펌웨어·제조사 도구·현장 옵션/교정/보정·시료 경로·실측 원본은 사용자/제조사/시험소가 제공할 입력이다. 수집 담당은 필요한 항목과 공개 근거를 정리하고, 파이프라인 담당은 현장 통합·실측 검증에 연결한다. 내부 자료를 인터넷의 유사 제품 자료로 대체하지 않는다.

최신 지시를 GitHub에 올린 사실과 다른 계정의 실행 중인 에이전트가 이를 읽고 적용한 사실은 별개다. 수집 담당은 적용한 지시 SHA를 반환해야 하며, 그 전에는 로컬 수집의 변경 적용 여부를 미확인으로 유지한다.
