# DGM VirtualLab 구현 계약

목표: 실제 장비 없이 자동화 코드를 개발하고, 같은 DeviceSession API를 사용하는 현장 프로파일로 전환합니다. 이번 범위는 하나의 공유 상태에 연결된 삼성 WLAN AT, 분석기, USB 파워센서, RF 발생기, ODA 전원, OSP 경로, CO3000 턴테이블·마스트입니다.

## 완료 기준

1. 기존 생산 드라이버가 모의 AT/SCPI/모션 peer와 통신합니다. 알 수 없는 명령은 거절하고 실제 네트워크·USB·시리얼을 열지 않습니다.
2. WLAN 6GHz HE160 송신·정지, 출력 변경, 경로 손실, 각도·높이·편파가 계측값에 반영됩니다. RF OFF와 차단 경로에서는 잡음 바닥을 읽습니다.
3. 같은 시험 함수가 VirtualLab.open 또는 HardwareLab.open을 주입받습니다. 실장비 모드는 별도 완성된 프로파일과 명시적 실행 코드가 필요합니다.
4. 정상·예외·취소·통신 실패·모션 고착·정지 실패를 검사합니다. 결과는 실행별 새 폴더에 보존하고 실패와 미확인 종료를 성공으로 기록하지 않습니다.
5. 설치된 wheel에서 CLI 실행과 결과를 검증하고, 문서·오프라인 설치 묶음·GitHub를 갱신합니다.

## 설계와 제한

공유 World → 엄격한 protocol peer → 기존 native driver → DeviceSession → 재사용 가능한 시험 recipe 순서입니다. 장비별 연결은 독점하며 서로 다른 VirtualLab 인스턴스는 상태를 공유하지 않습니다. 종료 시 transport close와 출력 OFF를 구별합니다.

모델은 결정론적 동작 모형입니다. 합성 대역 전력·단순 방향성·경로 손실로 개발 중 인과관계를 검증합니다. 실제 OFDM 파형, 검파기 응답, 반사·다중경로, 교정, 측정불확도, FCC 판정은 재현하지 않습니다. 모델 식·인수는 문서와 결과에 남깁니다. channel_argument=17과 6.035GHz의 연결은 이 가상 시나리오의 명시적 대응이며 삼성 전 모델에 적용하는 숫자표가 아닙니다.

Bluetooth·셀룰러·NFC·UWB의 물리 프로토콜/송신 모사는 이번 WLAN 통합 버전에 포함하지 않습니다. 다른 native 드라이버의 실제 제어 지원과 통합 simulator 지원은 별개입니다.
